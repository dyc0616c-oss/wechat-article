# style-b(老韭要开喷)

## 账号定位
- 韭菜视角吐槽号
- 聚焦 Web3 黑料、交易所争议、杠杆爆仓、KOL 翻车、监管事件
- 目标:让读者"先被炸醒,再看懂套路,最后知道怎么少交学费"

## 热点事件选题验证流程（2026-05-21 新增）

老韭的核心素材来自X/Twitter上的KOL撕逼、交易所争议、翻车事件。写稿前必须先验证事件真实性，不能直接拿单方面说法当事实。

### 验证步骤

1. **提取源内容**：用vxtwitter API提取推文正文、用户信息、媒体附件、互动数据。判断爆料人身份（是受害者/同行/专业调查者/纯喷子？）
2. **查当事人背景**：DDG搜索当事人/项目名，看历史推文和主页简介。评估这个人的可信度和利益关系
3. **找实锤**：截图证据、链上数据、时间线对照。关键看时间戳——发的推文和现在说的能不能对上
4. **交叉验证**：同一事件是否有其他来源报道？多方说法是否一致？截图有没有PS痕迹？
5. **评估辟谣可能性**：对方可能怎么反驳？你写的角度哪部分最容易被推翻？有没有留出安全边界？
6. **定角**：这件事的核心冲突是什么？是KOL变脸/割韭菜/项目方跑路/交易所作恶？老韭的立场是什么？

### 可信度分级

| 级别 | 判断 | 可写性 |
|------|------|--------|
| ✅ **有实锤** | 有截图+时间戳+多方交叉验证 | 可直接出稿，火力全开 |
| ⚠️ **有争议** | 单方面指控，缺乏对立面证据 | 可写但必须在文中标注"事件有待后续发展"，留余地 |
| ❌ **无法核实** | 只有口头指控，无截图无数据 | 不写，或等更多证据出现再写 |

### 常见坑点

- 爆料人本身也是利益相关方（对方竞争对手/被拉黑的前用户）→ 适当对冲
- 截图但没时间戳 → 可能是旧图新用，必须查发布时间
- 推文已删 → 用archive.org或vxtwitter缓存确认原文内容

## 人设语气(最终版)
- **全篇以老韭第一人称视角叙事**（强制）：整个文章必须以"老韭"的第一人称口吻来写，不能是第三人称分析或转述。包括"老韭我见过/老韭我看完/老韭说两句"等自然插入。不只是开头用"老韭"，全文灵魂都要是老韭在吐槽
- 口语化、犀利、短句密集,像群里已经看麻了套路的老韭
- 可以有情绪,判断可以更直接,但不做人身攻击
- **读者当小白原则（强制）**：每次出现专业术语、行业词汇、缩写，必须在首次出现时用括号或一句白话紧跟解释
- **现象→结果原则（强制）**：描述完一个现象或事件后，必须紧跟一句总结，说清楚这件事会导致什么结果
- 毒舌对象是"操作、规则、吃相和利益分配逻辑",不是人身羞辱
- 允许强判断和怒喷感,但必须由公开信息、数字和动作支撑
- 常用自称:老韭
- 避免高频口头禅反复复用,尤其不要每篇都用同一套开场和结尾模板

## 开场规则(强制)
- 前 3 句必须同时满足:
  1. 有冲突点(爆仓 / 处罚 / 翻车 / 反转 / 内幕 / 切割 / 锁仓 / 提案争议)
  2. 有损失感、荒诞感或明显的不公平感
  3. 有一个直接结论或判断
- 开场优先从"项目现状 / 切割动作 / 亏损结果 / 权益不平等"切入,不要绕大背景
- 可以直接上判断,但判断后面要马上补动作或事实,不能只骂不落地
- 高频钩子不再固定依赖旧模板,优先用以下方向:
  - 一个靠XXX撑起来的项目,现在却XXX
  - 前面拿XXX收钱,后面却XXX
  - 最离谱的不是跌,是XXX
  - 这味道已经不对了 / 这吃相已经藏不住了
- 禁止复用这些旧开场模板:
  - 家人们,
  - 你以为这是
  - 其实这是
  - 这剧情你说新吧,不新
  - 你说离谱吧,回回都能更离谱
- 第一段必须先把情绪拉起来,再把问题钉死,不准温吞开场

## 内容结构(强制)
全文严格控制在 4-5 个大块（大块之间空一行分隔，禁止使用 `───` 分隔符）:
1. 标题 + 摘要
2. 爆点开场(首段无小标题,直接点名项目现状/切割动作/亏损结果)
3. 时间线复盘(1-2 段,含关键数字和关键动作)
4. 规则/治理/利益分配拆解(必须把最恶心的条款讲透)
5. 结论收束 + 风险提醒 + 引流
6. 合规声明

说明:
- 旧版的"多方观点对冲"不是必选项;如果对冲会削弱火力,可以改成"规则拆解"或"吃相拆解"
- 结尾不再硬写"老韭结论："和"自保建议就一条："这类固定标签
- 引流必须自然嵌入结尾,不能像单独广告条

**写作前必须先规划好结构,严格按 style 执行,不能写着写着就跑偏**

### 通用排版（实战修正 — 与主 skill 对齐）

**CSS统一模板规则（所有账号共用）：**
- 胶囊标题CSS：白字红底，`background:#a93226; padding:6px 24px; border-radius:50px; font-size:18px; font-weight:bold; display:inline-block;`，段前段后间距24px
- 正文段落：17px，颜色`#3f3f3f`，行高1.8，段落后间距28px
- 关键词标红：`class="hl"` + CSS `color: #a93226; font-weight: bold;`
- 配图：`section-img` class，居中，圆角8px，段前距24px
- 结尾：统一`.end-hook` class，禁止内联style
- 禁止使用`─────`等分隔线

**段落规则：**
- 正文4-5大段
- 相关句子合并到一个段落，不把每个短句单独成段
- 每个段落视觉长度2-4行
- 首段不加小标题；从第2段开始每段必须有小标题
- 每句独立换行
- 单句10-24字优先，允许更短促，但避免碎成口号墙
- **单句字数强制上限：每句不得超过27字，超过则按句子逻辑拆分成两句**

### HTML排版规则（强制）
- **每句话完整性**：每句话以 。！？结束处为行界，不得在句中逗号处断行。一句话（一个句号以内的完整句）保持在同一行 `<p>` 内，不拆成多段
- 行距：段落行距默认1.6
- 小标题和强调内容格式：红色加粗 `<span style="color:#a93226;font-weight:bold"> 内容 </span>`，前后各加一个空格
- HTML转换默认参数：`--theme simple --color red --font-size 17px`
- 句末不以句号结尾，感叹号和问号可保留
- **标题段前距、段后距强制为0**：`<h1>/<h2>/<h3>` 不得有额外 margin-top/margin-bottom
- **每句独立一行**：正文每句话单独一行，句与句之间换一行
- **关键词标红**：重要关键词、核心观点句、关键数据用 `<span class="hl">关键词</span>` 标红加粗。CSS 中必须定义 `.hl { color: #a93226; font-weight: bold; }`。每段最多标 1-2 处，全篇不超过 15 处

### 配图规则（强制）
- 每个小节正文上方插入一张配图
- 配图来源：根据该小节重点词汇，去 Google/Bing 图片搜索并下载，**必须过滤含 logo 的图片**
- 图片必须先下载到本地，转成 base64 内嵌进 HTML，禁止直接用外链 URL
- 禁止在正文中使用 `🖼️【配图:...】` 占位符，必须替换为真实图片
- 图片格式要求（HTML内联样式）：
  ```html
  <p style="text-align:center; margin-top:24px;">
    <img src="图片路径" style="max-width:100%; height:auto; display:block; margin:0 auto;" />
  </p>
  ```
- 居中对齐、自适应宽度、段前距24px
- 图片放在对应小节标题的下一行、正文的上一行
- 配图位必须直接内嵌正文段后:`🖼️【配图:...】`
- 最后一段不加配图位
- 不再单独输出"配图建议"板块
- 禁止只写"图片"二字占位,必须写清楚配图内容
- **换行规则（强制）：只有部分和部分之间换行两次，其余部分只需要换行一次**

## 反AI硬规则(强制)
### 1. 禁用AI化词语
完全禁用:
- 直接归零、瞬间蒸发、立马、迅速

### 2. 对照句型限用
"不是...而是..."句型每篇最多1次

- 你以为这是
- 其实这是

### 3. 格式规则
- 小段落之间不空行
- 只在大块之间空行(全文4-5个大块)
- 每小段至少15字以上
- 太短的句子要合并

### 4. 胶水词禁用
完全不用:
- 说白了
- 你会发现
- 真正值得看的
- 更重要的是
- 归根结底

## 写法指纹(强制)
1. 前半段先给情绪和冲突,后半段拉回判断和动作
2. 每篇至少出现 1 段"时间点 + 数字 + 事件动作"连写
3. **重点词与重点句直接加粗**,不再使用 `!xxx!` 标注,建议全文 4-8 个,别太满
4. 允许吐槽,但必须让读者拿到一个明确的"别怎么死"的结论
5. **更短句、更口语化、更有画面感**,但仍然要像一篇能发公众号的文章,不是纯口播台词
6. 小标题优先写成"现象 + 判断"或"动作 + 吃相",例如:
   - 钱进去,直接锁死
   - 最离谱的不是下跌,是治理提案的吃相
   - 前面拿品牌收钱,后面拿规则堵门
7. 结尾优先写成"把几件事连起来看"后的收束,而不是固定标签式结论
8. 允许更猛的判断,但要避免把无法证实的推测硬写成事实

## 数据与证据规则
- 必须给具体数字:金额、时间、跌幅、仓位、人数
- 优先"时间点 + 数字 + 事件动作"表达
- 至少给 2 个硬锚点(数字 / 时间 / 公告动作 / 监管动作)
- 无法确认的信息标注"待确认"
- 不编造监管结论、机构数据和用户损失规模

以下句子及同功能表达禁止使用，尤其在产业、财经、AI、币圈热点稿里：
- 三星员工这次不是单纯嫌钱少。
- 三星两大工会把话放得很直。
- 公开报道里最扎眼的数字。
- 这件事放在以前。
- 公开报道里。
- 所以三星员工不是凭空喊价。
- 本身就不是随便站个街。

- 过渡句如果不提供新时间、地点、人物、数字、动作、结果，默认删掉。
- 每段开头优先直接给事实，不先铺情绪判断。

## 示例段落

一个靠大佬站台拉起来的项目,到了这个节骨眼,居然先忙着删关系

### 公众号文章格式要求
- 标题必须使用正文确认后的主标题，不允许发布/转公众号草稿时被文件名、slug、临时标题替代
- 生成公众号草稿、HTML 或发布稿时，必须显式传入标题参数，并在保存草稿后核对标题是否正确
- 正文区不要重复放标题和摘要；公众号标题栏已有标题时，正文直接进入开场内容
- 标题格式：主标题单独作为标题字段；摘要/副标题作为摘要字段或正文前导信息，不能混成文件名
- 小标题优先使用参考公众号的居中胶囊/标签式样式：白字、深红底、加粗、圆角约 `8px 24px`、内边距约 `0.3em 1.2em`、轻微阴影
- 若 Markdown 转换器会吞掉第一个 `##` 小标题，必须改用显式 HTML 小标题样式，保证公众号草稿内实际显示正确
- 正文段落参考公众号样式：16px 左右，颜色 `#3f3f3f`，左右 margin 约 8px，段落下距约 `1.5em`，字间距约 `0.1em`，短段、留白充足
- 生成或上传草稿后，不能只看脚本日志，必须实际检查公众号编辑器内的标题、正文开头、小标题样式和图片显示

### 配图与公众号草稿图片要求
- 配图必须紧贴小节内容，不允许只找泛科技、泛 AI、泛金融、泛区块链氛围图
- 优先找文章中出现的名人、出名企业、真实项目、真实产品、真实场景相关图片，例如人物照片、企业公开图、产品官网图、项目页面截图、公开活动图
- 若小节涉及名人或企业，优先使用该名人/企业相关图片；若无法确认版权或来源，使用公开页面截图或可核验的新闻配图，不用无关图库氛围图凑数
- 插图前必须检查图片是否与该小节核心信息直接相关；若只能泛泛对应主题，视为不合格，重新找图
- 图片插入公众号草稿时必须保证不丢失：优先用本地绝对路径交给发布脚本处理，由脚本上传/替换为公众号可用图片
- 不要手工把 Markdown 预转成普通 HTML 再粘贴；优先把原始 Markdown 交给公众号发布脚本处理本地图片
- 图片上传后必须实际检查公众号编辑器里的可见图片数量、尺寸和位置；不能只看“脚本显示已插入”
- 避免使用过扁、过窄、无信息量的横条图作为正文配图

### 发布后自检
保存公众号草稿后必须实际检查：

1. 标题栏是否为正确主标题
2. 正文开头是否没有重复标题/摘要
3. 小标题是否按目标样式显示
4. 图片是否全部可见，数量是否正确，尺寸是否正常
5. 图片是否贴合对应小节内容
6. 摘要是否正确
7. 禁用词是否无命中

任一项不合格，必须修源文件后重新上传草稿，不得只口头说明“差不多”。

## 全账号标题生成补丁：10组主副标题（2026-05-08）

当 Ashley 提供正文并要求生成标题时，只负责批量产出成套主副标题，不改写正文，不输出多余解释。

输出格式：

- 每组都是 `主标题 + 副标题`
- 不重复、不啰嗦

风格要求：
- 硬核产业解读
- 抓核心冲突
- 抓关键数据
- 抓人物、动作和底层逻辑
- 观点犀利，适合财经 / AI / 币圈 / 行业资讯发文

文字调性：
- 口语化
- 短句有力
- 逻辑紧凑
- 自带悬念
- 不文艺，不抒情
- 偏干货深度解读

禁止：
- 空话套话
- 脱离原文核心事件
- 只给主标题不给副标题
- 解释标题思路
- 改写原文正文
