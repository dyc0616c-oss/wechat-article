# 风格学习工作流

## 目标
从用户提供的 5-10 篇历史公众号文章中，提炼一个可复用、可执行、可交付的 style 文件。

## 输入
- 公众号名
- 5-10 篇历史文章
- 可选：账号定位说明、目标读者说明
- 可选：用户特别强调的优化方向（例如：更真人、更故事化、减少流水账）

## 提取维度
1. 标题
   - 长度
   - 常见句式
   - 情绪强度
   - 是“先抓人，再给信息点”，还是偏稳健说明

2. 摘要
   - 长度
   - 是信息差型、观点型还是钩子型
   - 是补充标题，还是重复标题

3. 首段写法（新增，重点）
   - 首段是情绪切入、问题切入、判断切入，还是背景切入
   - 首段是否像真人手写
   - 是否存在明显模板开头
   - 首段是否能快速把读者拉进来

4. 正文结构
   - 段落数
   - 是否一句一段 / 短段落推进
   - 每段平均句数
   - 是否有明确主线
   - 是否有流程感 / 带路感
   - 是不是容易写成流水账

5. 语言风格
   - 口语化程度
   - 是否犀利 / 稳健 / 故事化 / 教程化
   - 高频词与常见句式
   - 是否常用反问、转折、轻吐槽、带路句
   - 是否像真人在讲，还是像AI在总结

6. 叙事与判断（新增）
   - 文章是平铺信息，还是有故事推进
   - 判断是否落在具体事件中
   - 是否喜欢讲抽象大道理
   - 是否会把复杂概念翻译成人话
   - 是否能从“热闹”拉到“变量/门道/路径”

7. 排版风格
   - 重点句是否高亮
   - 重点词是否高亮
   - 小标题是否存在
   - 小标题是正式目录，还是口语化带路句
   - 是否高频分段、适合扫读

8. 结尾结构
   - 是否有引流钩子
   - 是否带二维码
   - CTA 风格
   - 结尾是具体判断、路径总结，还是鸡汤/空话

9. 图片策略
   - 封面图风格
   - 正文图风格
   - 图文插入位置
   - 图片是装饰，还是承担节奏切换作用

10. 禁用模式（新增）
   - 明显AI腔
   - 模板化背景开头
   - 流水账写法
   - 大道理泛滥
   - 该账号不该出现的表达方式

## 输出
- 生成一个 `style-x.md`
- 更新 `references/styles/account-style-map.json`
- 给用户回执“这个 style 学到了什么”
- 明确写出：
  - 必须学习的点
  - 建议学习的点
  - 不要学偏的点

## 注意
- 不要只总结抽象形容词，要总结可执行规则
- 风格总结优先写成规则，而不是散文描述
- 不只分析“长什么样”，还要分析“怎么写、怎么推进、怎么避免AI味”
- 如果用户明确要求“更真人、更故事化、更流程化”，必须在 style 中单独固化成规则，而不是只写一句概括
