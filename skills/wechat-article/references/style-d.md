# style-d(迷因百科)

## 账号定位
- 双线运营：**迷因/热梗拆解线** + **黑料/爆料喷人线**
- 迷因线（主）：迷因/热梗/小词条/小现象拆解号。核心任务：用一个看起来很小的梗、词、名字、情绪点，拆出背后的传播逻辑、注意力迁移、叙事变化和赚钱逻辑
- 黑料线（次）：行业黑料/平台暗箱操作曝光号。核心任务：用老韭视角，把交易所/项目方/机构的骚操作摊开，证据链摆出来，最后喷一句。读感要像「被坑过的老韭菜在群里扒皮」，不是「正义记者做深度调查」
- 不是知识科普号，也不是币圈喊单号，更不是行业研报号
- 读感目标：先让人觉得"这玩意有点意思"或"这操作真特么骚"，再让人看懂"背后到底发生了什么"

## 核心写作目标
- 用小切口讲大变化,不要上来就讲大道理
- 标题先勾人,再给信息,不做百科词条式命名
- 首段先把人拉进来,不急着下定义
- 正文不是解释概念,而是拆"为什么这个梗/词/现象开始值钱"
- 少行业报告味,少推广味,少币圈喊单味
- 保持轻松、有梗、有判断,但不乱抖机灵
- 让读者看完后能带走一句话,而不是只记住一堆解释

## 标题规则
### 标题第一原则
- 必须先有钩子,再谈信息密度
- 标题核心是让人点进去,不是提前把概念讲完

### 标题要素
每个标题至少命中 2 个,最好命中 3 个:
- 反差
- 画面
- 利益 / 结果
- 冲突
- 情绪
- "大家还在 X,别人已经 Y" 的时间差感

### 推荐标题结构
- 你的 X 还在......,别人已经......了
- 当大家还在......时,有人已经......了
- 一个看起来很小的......,背后其实是......
- 这不是......,这是......
- ......突然火了,背后藏着......
- **疑似XX,[时间]+[动作]+[数字]**(如"疑似币安上币组钱包,18天后买入8万代币")
- **直接说事实型**:不卖关子,直接说发生了什么+关键数字

### 禁止标题
- 什么是什么
- 为什么会这样
- 一文看懂某概念
- 某术语是什么意思
- 过于平铺直叙
- 像培训课、行业周报、百科词条

### 标题比例
- 悬念 / 利益 / 观点 = 6 / 2 / 2
- 默认优先给"悬念 + 反差"型主标题

## 首段规则
- 第一段必须先让读者觉得:这事不只是个小梗
- 优先写法:
  - 一个奇怪现象
  - 一个反常识判断
  - 一个群聊里会出现的场景
  - 一个看起来离谱、但背后确实有变化的点
- 开头禁止:
  - 下定义
  - 讲长背景
  - 解释术语
  - 摆大道理

### 推荐开头感觉
- 你以为这只是个新梗,其实它已经开始改写一套玩法了
- 最近有个变化很小,但味道不对
- 这事看着像个词语问题,往下扒开却不是那么回事
- 大多数人还把它当热闹看,但聪明人已经顺着这个变化去拿结果了

## 正文结构规则
- 默认正文长度：600-900 字
- 默认 1-2 句一段
- 超过 3 句要检查是否开始讲废话
- 默认采用 4 段推进：
  1. 钩子 + 现象
  2. 把小切口讲清楚
  3. 抬升到更大的逻辑
  4. 用一句判断收走
- 文章要像"越看越大"，不是"越写越散"
- 每篇只保留一个主切口，不要又讲梗、又讲价格、又讲项目、又讲创始人，最后散成拼盘
- **增加关键细节**：在关键转折处补充具体细节（如"前脚刚买，就有大量的KOL疯狂跟单"）

## 合约地址输入工作流(style-d 专用)
当用户直接发送一个 meme 币合约地址时,不得直接起稿,必须先按以下顺序执行:

1. 先去 **GMGN** 搜该合约地址
   - 必须先看 **所有链**,不要先默认某一条链
   - 优先看 **市值最高 / 热度最高** 的那条
   - 默认重点看 **BSC 链** 的表现
   - 查:链、币名、ticker、市值、涨跌、交易量、持币人数、上线时间、关联链接
2. 再去 **X / Twitter** 搜相关内容
   - 查:谁先提到这个币、哪条推文把它带起来、绑定了什么梗/热点/人物/事件、社区现在怎么讲它
3. 先判断这个币最值得写的"小切口"
   - 不是直接写"这个币怎么样"
   - 而是先找"它为什么会被讨论、为什么会被炒、它背后真正被炒的是什么"
4. 最后再按 style-d 出稿
   - 先用钩子把人拉进来
   - 再讲这个小切口
   - 再抬到更大的传播/叙事/注意力变化
   - 最后落一句判断

### 注意
- style-d 写 meme 币,不是写项目介绍,不是写基本面报告
- 默认隐藏后台搜索动作,不得在正文里写"我去GMGN查了""推特上有人说"这类素材痕迹
- 若查不到足够叙事,只能写成"热度现象观察",不能硬编故事

## 语言风格规则
- 口语化、短句、少解释腔
- 像一个懂行的人在群里把事讲明白
- 可以有梗,但不是为了搞笑而搞笑
- 可以调侃现象,但不搞攻击、不低俗、不油腻
- 要有"我有判断"的感觉,不能像素材搬运

### 推荐连接词
- 你别看
- 问题就在这
- 结果有人一翻,直接翻出个大的
- 那还说啥了
- 话不多,但气氛没了
- 这下盘面就不演了
- 说到这,味道就出来了
- 这就很 BSC
- 然后事情开始不对味了

### 禁止风格
- 过重学术腔
- 过重解释欲
- 过重行业黑话
- 推销味 / 币圈喊单味
- "香饽饽 / 能冲 / 大佬稳拿 / 共识拉满" 这类过度营销词
- 写成"知识百科"或"产品宣传稿"

## 反AI与反营销硬规则
### 1. 不准把迷因百科写成喊单文
- 禁止明显"币圈带单味"
- 禁止写成"这个币能冲、这个盘能上、热度越炒越高所以要抓住"这类营销节奏
- 可以讲传播和情绪,不可以顺手把稿子写成推盘文

### 2. 不准上来解释概念
- 迷因百科的第一任务不是给术语下定义
- 必须先写"为什么这个东西突然重要了"
- 定义只能作为中段补充,不能作为起手式

### 3. 少用标准答案句型
- 避免:什么是什么、为什么会这样、一文看懂、某某是什么意思
- 避免一上来就把答案写死,要让读者有往下看的冲动

### 4. 不准写成大而全
- 每篇只围绕一个"最值得写的变化"展开
- 不做百科全书,不求面面俱到

## 叙事与判断规则
- 不是先解释概念,而是先判断这个现象为什么值得写
- 不是围着定义打转,而是围着"变化"打转
- 不是先讲知识点,而是先讲反差和结果
- 不是把标题写清楚就完了,而是必须写出点进去的冲动
- 不是为了完整而完整,而是为了传播去组织信息
- 遇到 meme 币 / 日期梗 / 事件梗 / 人物梗时,必须先判断:市场到底在炒符号本身,还是在炒符号背后的情绪来源
- 如果叙事源头来自关键人物发言、书摘、采访、评论区扩散,必须先把"源头内容 -> 社区共鸣 -> 二创扩散 -> 链上币化"这条链写清楚
- 允许加入明确主观判断,但主观判断必须建立在已抓到的传播链和市场行为上,不能空喊观点
- 对 BSC 相关题材,允许写出平台特有的依附关系、信号依赖和情绪结构,不要把所有链都写成一个味道

## 正文骨架轮换规则(新增,强制)
style-d 不能所有题都套同一条"小词 -> 大变化"骨架,必须先判断题材,再选骨架。

### 骨架 A:小词 / 新命名型
适用:词元、智脑、术语定名、中文命名
结构:
1. 这个词为什么突然被看到
2. 它为什么不只是个词
3. 它背后哪一层叙事开始变贵
4. 最后落到一句"命名背后是分配变化"

### 骨架 B:热梗 / 热词爆火型
适用:突然刷屏的梗、群聊热词、社群梗图
结构:
1. 先写这梗为什么看着离谱
2. 再写为什么它能传这么快
3. 再抬到注意力迁移 / 传播结构
4. 最后落到"这个梗为什么不是普通热闹"

### 骨架 C:名字 / 符号 / 书名型
适用:币名、书名、人物标签、代号、口号、日期梗
结构:
1. 这个名字/符号为什么会被重新盯上
2. 它最初是被哪条内容、哪个人物、哪段记忆点燃的
3. 市场到底借这个名字/符号在炒什么
4. 名字和叙事之间怎么发生绑定
### 骨架 D:小现象 -> 大市场动作型

适用:投票、截图、评论区异动、某条推文、一张图

结构:
1. 先写这个小现象
2. 再写为什么这现象值得写
3. 再抬到市场动作 / 资金动作 / 注意力动作
4. 最后落到"这不是小事,是前兆"

### 骨架 E：黑料/爆料型（老韭喷人线专用）

适用：平台暗箱操作、项目方割韭菜旧账、行业骚操作被扒

结构：
1. 先扔一个最炸的画面/数字/事件——不要铺垫，直接说「XX翻旧账了/被人扒了」
2. 交代事件经过——谁干的、怎么干的、受害者是谁、损失多少
3. 补证据链——链上数据/合约地址/截图/客服回复，一样一样摆出来
4. 抬升到更大的逻辑——这不是个例，是这个平台的惯用操作/行业通病
5. 用一句能传播的吐槽收走——「旧账没清完之前，谁敢再信一次」

### 多源调查工作流（黑料/爆料型专用）

当素材来自多个 X/Twitter 链接时，执行以下步骤再动笔：

1. **vxtwitter API 批量提取** — 用 execute_code + subprocess 并发提取多条推文，确认事件全貌（谁是源头、谁在补充、谁在怼、关键数字和合约地址是什么）
2. **搜索补充报道** — DuckDuckGo 搜事件关键词，找至少2-3篇不同来源的报道/讨论帖，验证事件真实性
3. **链上数据核实（如有合约地址）** — 正文中提到的合约地址/链上数据必须来自可查证的来源（如推文中提供的合约地址+验证截图），不能仅凭文字描述
4. **事实核查强制** — 黑料/爆料最怕假料反转。文中每个数字（金额、Gas费、未归还资金）、每个声明（"客服说""规则是"）必须有两个以上独立来源交叉验证。有任何一个事实无法核实，禁止交付
5. **素材痕迹清洗** — 正文中不得出现"有篇帖子说""某条推文里讲到""据爆料""据媒体报道"等痕迹。改写为直接叙事，仿佛账号自己发现和验证的
6. **挖掘官方回应** — 爆料后一定要搜相关方是否有官方回应。有时回应藏在Help Desk客服号而非主号里。搜索X账号时同时搜主号(@okxchinese)和客服号(@OKXHelpDesk_cn)。官方回应是文章的关键证据链——有回应写回应内容+反驳点，没回应写沉默本身也是新闻

   ⚠️ Help Desk搜索经验（2026-06-01实战）：OKX客服账号 @OKXHelpDesk_cn 对2022世界杯链上合约争议有官方回应，在文章评论回复中而非单独发帖，容易被忽略。搜索时除了搜主号名字+事件关键词，也要搜「HelpDesk」「客服」+ 事件关键词

### ChainThink系固定模块（2026-06-01 用户改稿确认）

以下为ChainThink官号/老韭要开喷在爆料类文章中的固定格式：

- **开头固定**：`ChainThink温馨提示：加密货币风险高，远离投机，保护个人财产`（独立成段，放标题摘要下方、正文首段上方）
- **结尾固定引流模块**：引导扫码进群 + 官网链接 `https://www.chainthink.cn/news`。具体文案参考：「想深扒更多奇葩瓜？群里更最新内幕、拆产业逻辑，扫码进群吃瓜！获取更多资讯新闻点击：https://www.chainthink.cn/news」
- **过渡标题**：可用「双方各执一词」做平衡叙事过渡，先用户投诉后官方回应，不偏信任何一方
- **结尾金句**：必须有一句可截图传播的短判断收束，示例：「你可以来亏钱，但是赚钱那就不好意思了」「旧账没清完之前，谁敢再信一次」「芯片能做出来，但用户拽不过来，这台电脑就只是块昂贵的电子摆设」。**禁止用安全反问收尾**（如「到底是真需求还是厂商在制造需求」）——没有信息增量的反问句没有传播力
- **措辞上限**：允许「吃相太难看」「大冤种」「说人话」「不是噶了」「这操作可太骚了」等口语化强情绪词，但必须有事实/数据/证据支撑
- **节奏**：每段字数比迷因线更紧凑，一句话能讲完不拆两句
- **正文100%以账号自身为源头**：用户原话「把这个东西想象成是你的原创」，禁止任何第三方来源痕迹

### 老韭喷人线 tone（黑料/爆料专用）

- 允许更强的情绪词：炸裂、骚操作、割韭菜、坑人、离谱、吃相太难看
- 允许直接引用受害用户的原话（加「」引用），增强真实感
- 允许反问、比喻、讽刺，但不能编造事实
- 句式推荐：短问句（"然后呢？"）、反讽句（"客服解释也很绝"）、对比句（"规则看着挺良心，翻脸更积极"）
- 收尾可以用"你怎么看"互动钩子，也可以直接甩一句判断收走
- 喷要有传播金句收束。如「你可以来亏钱，但是赚钱那就不好意思了」「旧账没清完之前，谁敢再信一次」——具体事件+一句扎心判断
- 禁止写成"文ge大字报"风格——有情绪但要有理有据，每句喷都要有证据支撑
- **允许多方说法并列**：用户投诉写一段，官方回应写一段，用「双方各执一词」类过渡段做平衡叙事，不偏信任何一方
- 正文节奏比迷因线更紧——每段字数越少越好（用户实战验证偏好），一句话能讲完不拆两句，两句能讲完不拆三段

### 使用规则
- 同类题材连续两篇,不得复用同一正文骨架
- 起稿前先判断题材归属,再选骨架
- 若写完后发现"换了词但骨架没换",视为未通过

### 迷因百科最重要的判断方向
- 这不是一个简单的 X 变化,而是 Y 开始变化了
- 你看到的是 X,真正值钱的是背后的 Y
- X 能火,不是因为它更标准,而是因为 Y 已经变了
- 一个词 / 梗 / 小现象能定下来,不是因为它讲得更好,而是因为它终于变重要了
- 当一个概念开始被重新命名时,往往意味着一轮新的叙事分配已经开始了

## 排版规则
- HTML转换默认参数：`--theme simple --color red --font-size 17px`
- 陈述句段尾默认不加句号
- 问句保留问号
- 情绪句保留感叹号
- 高频分段,适合扫读
- 首段默认不加小标题
- 后续小标题要像人话,不像目录
- **换行规则（强制）：只有部分和部分之间换行两次（用───分隔的大块之间），其余部分只需要换行一次**
- **关键位置配图**(在重要转折、关键数据、情绪高点处加图)

### 小标题推荐写法
- 没多久这盘就被谁谁谁自己浇醒了
- 结果最热闹的时候,本人出来拆台了
- 这事又把 BSC 的老毛病抖出来了
- 说到这,盘面就开始不对味了
- 前面大家还在认表哥,后面表哥自己出来辟谣了
- **疑问句式**(如"这个地址为什么会被盯上呢")

### 小标题禁止写法
- 一、事件背景
- 二、核心原因
- 三、后续影响
- 首先 / 其次 / 最后
- 最尴尬的地方是……
- 这波最有意思的，不是……而是……
- 有些什么什么看起来……其实……
- 这种东西起得快，死得也快
- 真正关键的不是……

## 重点词与重点句规则
- 每篇至少有 2-4 个重点词
- 每篇至少有 2-3 句重点句
- 重点词适合打在:
  - 最有传播感的词
  - 最能代表注意力迁移的词
  - 最值钱的逻辑转折
  - 最有记忆点的判断
- 重点句要能被单独截图传播

## 配图偏好
- 优先用:梗图、热词截图、媒体标题截图、社群讨论截图、反差感强的素材
- 不优先:纯数据图、太像报告配图的图、太正经的流程图
- 图片作用:强化"这事有梗、有反差、有传播感"

## CTA 风格
- 转发给还没看懂这个梗的朋友
- 留言说说你第一次看到这个词 / 梗时的感觉
- 如果你最近也在刷到这个现象,评论区聊聊
- 你还见过哪些"看似小、其实背后很大"的变化?
- **自然引导型**:"评论区聊聊,或者进群一起交流"
- **抛出延伸问题**:"为什么有的地址能成为'信号源',有的只能当韭菜呢?"

## 文末收束要求
- 结尾优先写成一句判断,再接一句延伸,再接 CTA
- 不要收得太软
- 不要直接变成进群广告
- 迷因百科的尾巴,重点是让读者带着一句"哦,原来是这么回事"离开
- **温馨提示放开头**:Meme币定义和温馨提示放在文章开头,不是结尾

## 禁用表达
- 一文看懂......
- 某某是什么意思......
- 值得注意的是......
- 在当前背景下......
- 这充分说明了......
- 总而言之......
- 赋能、抓手、闭环、矩阵化
- 香饽饽、能冲、共识拉满、大佬稳稳拿着

## 风险边界
- 不编造数据
- 不伪造来源
- 不作绝对化收益承诺
- 不把情绪传播写成官方背书
- 不把市场热度直接写成确定价值
- 信息不确定时标注:待确认
- **不要在正文中提到合约地址**（避免推广嫌疑）
- 不要写成复盘会纪要
- 不要为了显得会分析,把一句能讲完的事情拖成四句

## 验收标准
- 第一段能把人拉进来,不像教材
- 正文不是在解释概念,而是在拆"为什么它突然值钱了"
- 有轻松感、有梗感,但不过头
- 没有明显币圈推广味
- 没有明显 AI 解释腔
- 重点词、重点句、小标题真的落出来了
- 结尾有一句能带走的判断
- 读者看完会觉得:这不是一个梗,这是一个变化
- 如果是人物/书摘/推文驱动型 meme,读者看完必须能明确知道:最初是谁点火,社区怎么接梗,链上为什么会顺手币化

## 实战复盘补丁（2026-04-06 / 714案例 + 2026-04-08 / CZ手机号案例）
### 这类题最容易写偏的地方
- 不要把日期梗或人物周边梗写成抽象概念分析
- 不要只写链上价格,不写叙事源头
- 不要把社区二创结果,误写成源头本身
- 不要只讲"这个币火了",要讲"为什么这个符号会在这个时间点被重新点燃"
- 不要一上来就总结,先把场景讲出来
- 不要写流水账,一句话只干一件事

### 714案例的正确链路
- 源头: CZ 发新书节选
- 内容: 2017年7月14日 Binance 上线当天,开局先被卖单压脸
- 社区反应: 714 梦开始的地方 / The beginning of the story / 714没有买单全是卖单,现在也是
- 链上动作: 社区顺着情绪点把 714 做成 meme 币
- 最终判断: 市场炒的不是714这个数字本身,而是 CZ 新书里那段"差点翻车,后来成神话"的情绪反转

### CZ手机号案例的正确链路
- 源头: CZ 新书发布后,社区翻书发现旧手机号
- 社区反应: 支付宝验证 / 存通讯录 / 表哥联系方式 / 玩梗扩散
- 链上动作: BSC 顺手把手机号题材做成 meme
- 关键转折: CZ 本人亲自回复,说号码早就不用了,新主人可能是黑客或帽子叔叔
- 盘面结果: 题材被本人一句话浇醒,价格快速回落
- 最终判断: 这类盘很多时候吃的是接近核心人物的幻觉,一旦源头出来纠偏,情绪就会直接漏气

### BSC 题材的主观判断增强规则
- 写 BSC meme 时,允许加入平台气质判断
- 可以写: BSC 玩家高度依附 CZ / 何一 这套叙事系统
- 可以写: 很多 BSC meme 能不能涨,不只看内容本身,更看它跟双圣有没有绑定成功
- 可以写: BSC 很多时候不是纯社区自发生长,而是围绕双圣做阅读理解和情绪金融
- 但必须注意: 这些判断只能建立在当次抓到的传播链、评论区话术、链上反应之上,不能当万能套话

### 更像人写的开头规则（新增）
- 先开聊,不要先总结
- 先给场景,再给判断
- 多用"有人一翻书,直接翻出个大的"、"这老头居然"、"那还说啥了"这种活人口气
- 避免开头就写成分析摘要
- 开头要像群里刚看到这事,顺手讲给别人听

### 以后遇到类似题的写法SOP
1. 先找源头内容是谁发的
2. 再看社区是怎么重新命名、重新解释它的
3. 再看链上是怎么把这层情绪币化的
4. 如果源头本人后来回应了,必须把"回应前后盘面变化"写进去
5. 最后补一句主观判断: 这个平台为什么特别容易接这种梗
