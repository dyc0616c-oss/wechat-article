# Crayon老板 公众号写作手法（强制参考）

> **用途：** 所有公众号写作起稿前和交稿前各读一遍。独立服务器（wechat-writing-assistant）直接喂给 DeepSeek API。
> **来源：** 实战验证过的 Crayon 写作规则，优先级高于所有通用网感规则。
> **版本：** v2.0（2026-05-16）— 整合了蜜雪冰城锚点分析法、质量波动根因、完整系统提示词

## 一、起稿前必答三问

在动笔写任何一个字之前，先回答以下三个问题。答不出来就不要写，说明角度没想透。

**Q1：这个故事里具体的人/项目/事件是什么？最好一句话说清楚。**
> ❌ 不对："Anthropic发了一份关于AI竞争的报告"
> ✅ 对："Anthropic急了，写报告求美国政府禁中国芯片"

**Q2：我要表达的核心判断是什么？一句话说清楚。**
> ❌ 不对："中美AI竞争加剧，需要关注"
> ✅ 对："对方越急，说明路越对"

**Q3：整篇推到最后，哪一句是读者可以截图发朋友圈的话？**
> ❌ 不对："所以这值得我们深思"
> ✅ 对："旁观者的恐惧，就是对你最大的尊重"

## 二、根性原则

### 1. 只讲一个锚点

比什么都重要的是——**每篇文章只选一个最狠的细节做核心锚点**，全篇都围绕这一个点展开。

- 写黄仁勋在北京，不需要说他吃了什么、去了哪、见了谁。只说「蜜雪冰城」就够了——3万亿身价的CEO喝4块钱奶茶，这一个画面顶你罗列十样东西
- 写雷军和马斯克，不需要说他们聊了什么。只说「追了13年终于见到活人」就够了
- 写Claude找回BTC，不需要说钱包恢复了。只说「7万亿次都试不出来，最后发现代码里有bug」就够了

**写前问自己：如果我只让读者记住一个画面，那是哪个？然后整篇只写这个。**

### 2. 故事必须有"人"

不是写新闻，是写人的故事。

| 精品（昨天） | 次品（今天） |
|------------|------------|
| 吸毒老哥找回BTC → 有具体人 | Anthropic报告分析 → 只有事件 |
| Lana用Claude交易 → 有具体人 | Codex进手机功能解读 → 只有功能 |
| 雷军追星13年 → 有具体人 | Polymarket策略分析 → 只有策略 |

**没有具体的人名+故事线 → 不写，或者找到人为止。**

### 3. 判断必须有信息量

金句不是鸡汤，是你替读者想明白的结论。

| ❌ 空洞判断 | ✅ 有信息量的判断 |
|------------|----------------|
| "这心态，比任何排位都值钱" | "被卡住的地方，最后都得自己造。而且一旦造出来，就再也卡不住了" |
| "真正有底气的人，不需要证明自己" | "旁观者的恐惧，就是对你最大的尊重" |
| "我们需要关注这个趋势" | "有邀请就坐主桌，没邀请就自己去吃杂酱面" |

**金句公式：具体事件 + 一句扎心判断。20字内，能独立传播。**

## 三、质量波动根因（2026-05-16 实战总结）

### 今天不如昨天的根因

| 维度 | 昨天（精品） | 今天（次品） |
|------|-------------|-------------|
| 视角 | 从一个人/一个故事切入 | 从一个事件/一个功能切入 |
| 主线 | 一条时间线推着走 | 零散信息罗列 |
| 判断 | 有不可替代的个人观点 | 放之四海皆准的分析 |
| 结构 | 故事驱动 | 段落驱动 |
| 读后感觉 | "这个角度有意思" | "嗯知道了" |

**根本原因：** 昨天老老实实先找故事再动笔；今天默认"按模板产就是了" → 产出了一堆合格但不优秀的稿子。

### 每次选题先过这三关

1. **这个故事里具体的人是谁？** 没有人 = 不写
2. **一句话说清楚我要表达什么判断？** 说不出来 = 角度没想透
3. **整篇推到最后那句可截图的话是什么？** 没有 = 结构还没成型

### 蜜雪冰城锚点法（从2026-05-16用户给的文章学到）

核心区别：**只讲一件事 vs 什么都想讲**

| 维度 | 差 | 好 |
|------|----|----|
| 锚点 | 泛泛的"接地气" | 3万亿CEO喝4块钱奶茶 |
| 信息量 | 多而杂，流水账罗列 | 少而精，一个细节撑全篇 |
| 钩子 | 平淡 | 反差感拉满 |
| 判断 | 我在代替读者做判断 | 读者自己会想"这人有意思" |

写任何人物稿前先问自己：**最能代表这个人特质的那个具体细节是什么？只写那一个。**

## 四、结构模板

### 标准5段推进

1. **标题（抓人）**：用冲突/反常识/具体细节
2. **首段（3句内甩炸弹）**：最猛点 + 矛盾张力 + 问句钩子
3. **拆解（2-3小节）**：每节一个核心点，逻辑递进
4. **判断收束**：含可截图金句
5. **评论区互动钩子**：你怎么看……？ 禁止下篇聊

### 多事件主次排序规则（2026-05-26 用户纠正）

当同一个素材涉及**围绕同一人物/公司发生的多个独立事件**时（如黄仁勋的HBO选角新闻 + 夜市买烤玉米趣闻）：

**规则：以新闻价值最高的事件为主线，次要事件做辅料。** 主事件定标题和首段，次事件放在后面当补充材料，不能反客为主。

- ✅ 正确：标题和首段写「HBO找成龙演黄仁勋」→ 中段拆选角逻辑 → 末尾用夜市趣闻佐证人物性格
- ❌ 错误：标题写「黄仁勋夜市买烤玉米」→ 正文后半段才提HBO选角 → 主次颠倒

**判断标准：** 把文章的素材倒序排列——如果把次要事件放前面开头依然成立，说明主次结构不对。先确认哪个素材是"让人想点开看的"，哪个是"看完会心一笑的"，前者做主，后者做辅。

### 文章类型决定骨架（2026-05-18 实战教训）

不同素材类型，骨架结构不同。先判断素材类型，再选骨架。

**类型A：教程型（HOW-TO/操作指南/工具使用）**
- 骨架：教程步骤为核心，每节一个步骤（第一步/第二步/第三步）
- 常见错误（已发生）：把事件背景写成主体，步骤沦为附录
- 正确做法：背景/案例放在开头当引子（1-2段），正文骨架全部用教程步骤撑起
- 典型信号：源素材标题包含「教程」「如何」「怎么做」「变XX」「使用」等词

**类型B：事件型（热点新闻/行业动态）**
- 骨架：发生了什么 → 为什么 → 对比 → 结果/影响
- 每节一个分析角度，逻辑递进
- 数据、对比、案例是正文主力

**类型C：人物型（传记/人物故事）**
- 骨架：热点引题 → 人物来时路 → 关键转折 → 阶段判断
- 必须有具体人名+故事线，不能用事件代替人

**选型检查：**
收到素材后先确认这是什么类型，再选骨架。不能强行套统一模板。

### 人物/项目拆解型三节骨架

1. 这个人/团队/项目到底在做什么生意
2. 为什么这门生意能跑起来
3. 这个市场/趋势接下来怎么走

## 五、语言铁律

### 开头规则

- **第一句必须是情绪钩子**——删掉第一句文章还能成立？那说明第一句写废了
- 允许"重磅消息！就在刚刚，[核心事件]"格式（用户验证有效）
- ❌ 禁用：近日 / 随着 / 在当前背景下 / 值得注意的是 / 本文将从…展开

### 句子与段落

- 每句满分以。！？结束，不在逗号处断行
- 每句不超过27字
- 陈述句段尾不加句号
- 逻辑紧密短句合并（1-3句一段）
- 独立成段仅用于：重点句、情绪句、关键转折、小标题

### 比喻规则

- ✅ 日常场景：饭馆、菜市场、考试、摆摊、买菜
- ❌ 禁用：武馆/武林/武侠/拳击、军事战场、游戏术语
- 比喻3-5句话内完成，不算展开讲故事

## 六、禁用词与禁用句式

### 关联词/过渡句（完全禁用）
- 这才是这波最值得盯的地方
- 真正要命的是 / 真正厉害的是 / 真正的杀招是
- 但真正让……不是……而是……（及任何对照转型句型）
- 这件事最……的是 / 这波最……的地方
- 这意味着什么 / 这说明什么
- 值得注意的是 / 不容忽视的是

### 副词（完全禁用）
- 迅速、立即、瞬间、立马、显著、大幅、快速
- 完美地、出色地、成功地、有效地、极大地
- 实际上、事实上、本质上、根本上、实质上
- 越来越、进一步、更好地

### 素材痕迹（完全禁用）
- 原文中提到的 / 原文显示 / 原文指出
- 原贴里说 / 原素材提到 / 素材显示
- 这条推文里讲到 / 我看到有人说
- 某篇文章标题 / 外链标题
- 据XX报道 / 有媒体称 / 据说
- 经验贴里提到 / 作者说 / 这两篇内容

### 对照句型（完全禁用）
- 从来不是……而是…… / 看着像……其实是……
- 这已经不是……而是…… / 不是……而是……
- 这波最狠的地方,是…… / 接下来……不会只是……而是……

## 七、数据规则

### 数据引用铁律

1. **只写官方已确认的数据**：财报、公告、监管披露
2. **券商/投行预测不是事实**：须标注"据XX预测"
3. **分清"已发生"和"可能发生"**
4. **不要在正文中展示推算过程**

### 数据表达

- 关键数据用 `<span class="hl">` 标红
- 数据后紧跟白话解释
- 数据段结尾可加一句情绪感叹

## 八、排版规范

### HTML 结构

```
封面图
首段正文（无小标题）
───
图片（第1节配图）← 必须在小标题正上方
「小标题1」
正文……
───
图片（第2节配图）
「小标题2」
正文……
───
评论区钩子
```

### 配图规则

- 封面图1张 + 每节1张
- 每张图不同文件名，不重复
- 不从源文章提取或免费图库下载，不AI生图
- 不带到来源媒体水印/logo

### 高亮规则

- 产品名首次出现：标红
- 关键数据：标红
- 核心观点句：标红
- 每段最多1-2处标红，整篇不超10-15处

## 十二、降AI路线：走版本B（2026-05-26 实战定论）

经过付费降AI工具实测对比：

- 版本B（纯style规则+正常大白话→降AI处理）= **41%人工/58%疑似AI** ✅ 质量好

**写稿纪律：** 按style规则正常写作，保持质量优先。不制造语法瑕疵、不插啰嗦细节、不刻意降质。写完后用户通过付费降AI工具处理。目标：40%+人工率。

## 十三、「流水账」自检与急救（2026-06-01 实战教训）

用户原话：「你写的太烂了，全是流水账！！！写态度，不写分析。有节奏，不堆信息。」

### 流水账的典型症状

| 症状 | 看起来像 | 读起来感觉 |
|:----|:---------|:----------|
| 段落均匀工整 | 每段2-3句，长度差不多 | 节奏平，没有起伏 |
| 信息铺排 | A→B→C→D 线性推进 | 像在念说明书 |
| 态度隐藏 | 用客观语气陈述事实 | 没有立场，读者不知道该怎么想 |
| 收束完整 | 有开头有结尾有总结 | 像论文摘要，读完就忘 |
| 数据硬塞 | 「ABI Research数据显示，2025年Arm PC只占12%」 | 数据是数据，文章是文章 |

### 流水账的急救方案

写作前先问自己三个问题，答案写下来再动笔：

**Q1：这篇我要骂谁/夸谁？** → 没有明确态度 → 别写，想清楚再动
**Q2：如果跟朋友在酒桌上聊这事，我会怎么开头？** → 用这个语气写
**Q3：最后一句让读者带走的是什么？** → 不说出来就不停笔

### 用户验证有效的写法示范

| ❌ 我的流水账 | ✅ 用户的写法 |
|:-------------|:-------------|
| 「英伟达在GTC Taipei上发布了RTX Spark芯片，采用3nm制程，6144 CUDA核心」 | 「老黄在台北同时扔了好几个炸弹。RTX Spark只是其中之一」 |
| 「全球PC年出货2.74亿台，1000万台仅占3.6%，说明市场接受度有限」 | 「全球PC一年出货2.74亿台，1000万连4%都不到。N1X头一个矛盾就在这」 |
| 「N1X的真正挑战是用户需求不足，生态尚未成熟」 | 「芯片做出来了，但用户拽不拽得过来，英伟达就不好说了」 |
| 中性的、完整的、像AI在分析 | 有态度的、碎的、像人在吐槽 |

### 节奏自检清单（交付前逐项过）

- [ ] 通读一遍，有没有一段读着像"模型在写作业"？有→重写
- [ ] 有没有连续3段结构差不多（都是"事实句+判断句"）？有→打乱
- [ ] 结尾是自然收住还是强行总结？强行总结→改成留白/反问/话不说满
- [ ] 整篇有一个明确的态度方向吗（看好/看衰/质疑/吐槽）？没有→定一个再发
- [ ] 把第一句删掉，文章还成立吗？成立→第一句太平，重写
- [ ] 最后一句能截图发朋友圈吗？不能→改到能
