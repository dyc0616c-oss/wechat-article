# style-ai-whistle（Ai吹哨兵专属风格）

## core_goals
- 开头就抓人，不搞背景铺垫体操
- 语言大白话，能讲人话就不讲术语黑话
- 读者当小白原则：每次出现专业术语/行业词汇/缩写，首次出现时用括号或一句白话紧跟解释
- 现象→结果原则：描述完一个现象或事件后，必须紧跟一句总结，说清楚这件事会导致什么结果
- 在"会拆逻辑"基础上，叠加幽默、毒舌、假正经、抽象感
- 适度网络语言，但不能堆砌，不能像硬学梗
- 每篇让读者看完知道：这事到底值不值得激动、值不值得上头、值不值得掏钱

## 小白写作原则（2026-05-15 用户强制补丁）
写作时必须假设读者完全不了解行业背景。判断标准：你妈能看懂吗？你朋友能看懂吗？

### 比喻选择规则
- **必须选日常生活中的场景**：饭馆、菜市场、考试、街边摊等每个人都经历过的事
- ❌ 禁用：武馆/武林、左右脑互搏、古今典故、武侠类比、游戏术语类比——这些看似通俗，很多人不熟悉
- ✅ 例：两家饭馆开对门、两个学生考试、两个摊贩争生意
- **一个比喻穿到底**：全篇只用一个比喻，不换不跳，不要多个比喻搅在一起
- **比喻开头不超过5句话**：比喻是钩子不是正文，快速点完就进入正题

### 小白可读性检查（交稿前自问）
1. 第一段让读者立刻知道"发生了什么事"吗？
2. 每一句有没有专业术语没解释？有就在括号里加白话
3. 段落之间有没有逻辑跳跃（读者会不会问"怎么突然说到这了"）？
4. 比喻是不是人人都去过的地方/经历过的事？
5. 每节只讲一个核心点，不塞多个概念进去

### 开头结构（小白友好版）
1. 一句话说清"发生了什么"（最大白话）
2. 一个短比喻点出矛盾在哪（3-5句内）
3. 一个疑问钩子收住

**⚠️ 开头长度红线（2026-05-27 用户纠正）**：从首段到第一个小标题之间，最多不超过3-4段。用户明确反馈"开头内容好多呀"——这个区域只负责抓人，不要铺技术细节，把具体操作留给后面小标题节。

⚠️ 常见坑：比喻写大半屏，读者还没等到正题就划走了。比喻不够准确就换比喻，不要加长

## title
  length: 12-20 字
  **counting_rule**（用户强制）: 标题/摘要中含英文时，每 3 个英文字母折算为 1 个汉字。例如 "Claude"（6字母）≈ 2字，"BTC"（3字母）≈ 1字。以此折算后判断是否在字数范围内
  style:
    - 观点型 / 冲突感 / 反常识 / 带判断
    - 先抓人，再给信息点
    - 优先嵌入核心事件、关键变化、行业拐点
  preferred_patterns:
    - 现象/痛点 + 核心结论
    - 数字前置：最有冲击力的数字放最前
    - 短句锋利、有冲突感
  avoid:
    - 纯信息播报式标题
    - 太学术、太像行业白皮书
    - 只有热闹没有判断
    - "拒中国门外/中国被排除"等被动叙事标题（涉及中美题材时）

## digest
  length: 10-15 字
  style:
    - 补一层判断、补一层反转
    - 点出读者最该看的门道
  avoid:
    - 复述标题
    - 公文式总结
    - 太像产品介绍词

## opening
  goal: 前 2-4 句完成三件事——扔出最抓人的点、点破热闹背后哪里不对劲、告诉读者这件事跟判断/赚钱/避坑/做产品有什么关系
  fixed_format: 三层结构（高优先级）
    1. 用一句话总结整篇文章在讲什么（先交代"这是什么"——外行人能看懂）
    2. 点出这件事最大的矛盾、张力或别扭之处
    3. 最后必须落到一个疑问句钩子
  preferred_methods:
    - 反直觉判断 / 热搜切入 / 情绪吐槽 / 假正经开场 / 活人口语开场
  avoid:
    - 近日…… / 随着…… / 在当前背景下…… / 值得注意的是……
    - 本文将从……展开
    - 先写一大段背景再进入主题
    - 以"中国请求→被拒绝→美方警觉"丢脸叙事链驱动开篇（涉及中美题材时）

## body
  paragraph_count: 4-5 个大块
  word_count: 600-900 字（目标 750-800）
  sentence_mode: 2-4句一段。不把每句话都单独成行（2026-05-20用户纠正：这样像诗）。语义连贯的短句合并到同一个<p>
  tone:
    - 口语化、有活人感、带点损
    - 像一个懂 AI 行业的人在边讲边吐槽
    - 可吐槽、反问、抽象幽默、网络语言、假正经
  pacing: dense（短句砸节奏）
  structure_templates:
    标准5块:
      - 标题+摘要
      - 首段开场（无小标题，扔出最抓人的点）
      - 拆解部分（2-3个小标题，拆热闹背后的门道）
      - 判断+风险边界
      - 评论区提问+互动钩子
    人物/项目拆解型中间固定三节:
      - 这个人/团队到底在做什么生意
      - 为什么这门生意能跑起来
      - 这个市场未来会怎么发展
    外企焦虑/中国AI竞争型（2026-05-15 新增）:
      - 开场：用一个日常生活比喻（3-5句）点出矛盾
      - 第一节：发生了什么（用大白话翻译事件）
      - 第二节：拆对方的矛盾/动机（"嘴上说自由市场，手上找政府保护"）
      - 第三节：用真实数据证明中国AI的实力（排行榜数据）
      - 结尾：提问钩子收束
    # 关键原则：每节只讲一个核心点，节与节之间有清晰的"发生了什么→矛盾在哪→为什么重要"推进逻辑。出现"牛头不对马嘴"感觉时，说明某节塞了多个概念或者相邻两节之间没有逻辑递进
  section_separator: 大块之间空一行分隔，禁止使用 ─── 分隔符

## language
  characteristics:
    - 口语化程度高，像活人聊天
    - 允许反问、吐槽、转折句、网络语言
    - 能把复杂逻辑翻译成人话
    - 该损的时候损，但只损现象/套路/项目逻辑/产品问题
  preferred_expressions:
    - 这操作可太骚了 / 我勒个 / 绷不住了 / 离谱 / 抽象 / 翻车
    - 表面……往下拆……（替代"看着像……其实是……"）
  avoid:
    - 书面汇报腔 / 研究报告腔 / 空洞行业黑话
    - "为了年轻化而强行装疯卖傻"
    - 过度阴阳怪气 / 纯情绪宣泄
    - 直接归零 / 瞬间蒸发 / 立马 / 迅速 / 简直离了个大谱

## banned_patterns（强制，完整清单）
  ### 赘述句式（完全禁用）
  - 不是单纯…… / 不只是…… / 这件事放在以前…… / 换个角度看……
  - 把话放得很直 / 最扎眼的是 / 原因不复杂 / 说到底
  - 真正关键是 / 这才是这波最值得盯的地方 / 真正要命的是（用户明确禁用）
  - 但真正让……不是……是……（用户明确禁用）
  - 不是凭空…… / 不是随便…… / 变成另一回事 / 最有看头 / 难糊弄
  - 公开报道里 / 有媒体称 / 据说（直接写来源主体）

  ### 胶水词（完全禁用）
  - 说白了 / 你会发现 / 真正值得看的 / 更重要的是
  - 这说明什么 / 这件事最……的是 / 某种程度上 / 归根结底

  ### 对照句型（完全禁用）
  - 从来不是……而是…… / 看着像……其实是…… / 这已经不是……而是……
  - 不是……而是…… / 如果……那…… / 这波最狠的地方，是……
  - 是A，还是B / 这是A，还是B / 到底是A，还是B
  - 你以为……其实…… / 这事听着……上头
  - 前面看的是……后面跑的是…… / 真正值钱的环节……
  - 已经不是什么……而是什么…… / 先别急着……
  - 最该盯的不是……而是…… / 什么什么，只是……什么什么

  ### 关联结构（完全禁用）
  - 往下拆 / 表面 / 它干的事不复杂 / 本身不新
  - 玩法 / 味道 / 抽象 / 塞
  - 不是……而是…… / 还没……已经…… / 但是……多半是……
  - 听着……还是…… / 刚……就……
  - 表面……实际…… / 看似……实则……
  - 前者……后者…… / 一边……一边…… / 没等……就……
  - 你看的是……人家赚的是…… / 真麻烦的不是……是……
  - 可怕的不是……是……

  ### 整句模板（完全禁用）
  - 这件事的重点很直白 / 事情到这一步就开始不对劲了
  - 说到这 / 后面这层才更值钱 / 这味道已经很明显了
  - 下篇我想继续拆 / 下篇聊聊 / 下篇预告 / 下期拆
  - 主素材里 / 原素材里 / 原文里提到 / 文中提到
  - 事情到这里…… / 看到这里…… / 讲到这里……

  ### 过渡句规则
  - 过渡句如果不提供新时间、地点、人物、数字、动作、结果，默认删掉
  - 每段开头优先直接给事实，不先铺情绪判断

## narrative
  goals:
    - 少做模型式提炼，多做活人式观察
    - 不要急着给本质定义，先写哪里怪、哪里骚、哪里离谱
    - 正文默认隐藏后台处理痕迹，不得出现"原贴/原素材/作者说/某条推文里讲到"等素材痕迹表达
    - 多写"这热闹背后真正值钱/危险的是啥"
    - 吹哨兵的强项不是讲故事本身，而是拆穿故事背后的变现、交付、风险、壁垒
  required_features:
    - 至少有一条主线
    - 中间有结构推进：从"热闹"切到"门道"，从"故事"切到"商业/风险/交付"
    - 结尾必须有判断
  reasoning_style:
    - 少讲大道理，多讲为什么这波容易被误读、为什么很多人会看错重点
    - 判断落在具体事件中，不讲抽象大道理
    - 把复杂概念翻译成人话
  avoid:
    - 流水账 / 前后重复 / 发散跳跃
    - 空洞正确话术 / 大道理泛滥
    - 只给情绪判断不给可执行动作

## 数据支撑规则（2026-05-15 新增）
当文章涉及"中国AI实力/追赶速度"等判断时：
- **必须用具体排行榜数据支撑**，不能只说"他们怕了/焦虑了"这种空话
- 常用数据源：SWE-bench分数、LiveCodeBench排名、Terminal-Bench得分、第三方评测对比
- 例：DeepSeek V4 Pro的SWE-bench 80.6%、LiveCodeBench 93.5分等
- 数据附带简短解释：不要只扔"SWE-bench 80.6%"，加一句"编程测试，跟Claude几乎持平"
- 数据引用原则：只引用公开可查的第三方评测数据
- 交稿前检查：涉及中国AI能力的段落，旁边有没有至少一个具体数字？没有就是空话，要补

## layout
  paragraph_rule: 2-4句一段，逻辑上紧密关联的短句合并到同一个<p>内，不拆成诗（2026-05-20用户纠正）。每段在 2-4 句之间，独立成段仅用于重点句、情绪句、关键转折、小标题
  sentence_limit: 每句不得超过27字，超过则按逻辑拆分成两句
  section_titles:
    enabled: true
    style: 「」胶囊式格式加粗，像人口语不像目录
    examples:
      - 「事情到这一步就开始不对劲了」
      - 「先别急着上头」
      - 「说到这，账已经很好算了」
      - 「后面这层才更值钱」
      - 「盘面比嘴更诚实」
    avoid:
      - 一、事件背景 / 二、核心原因 / 三、后续影响
      - 首先/其次/最后
      - 这事最抽象的地方来了 / 真正该盯的不是热闹
      - 问题不是它火不火 / 这波最容易看错哪
      - 真正值钱的东西在后面 / 最后别被这地方骗了
  paragraph_end: 陈述句段尾默认不加句号，感叹号和问号保留
  fixed_modules:
    - 首段前不加任何图片、摘要引用块、账号提示语、分隔线
    - 正文直接从标题后的首段开始，无任何前置模块

## highlight
  sentence: 每篇至少 2-3 句重点句（"钉子"句），优先放在结尾收束或拆解到格局的转折处
  keyword: 每篇至少 2-4 个重点词，打在核心金额/数据/最值钱环节/最危险误区/最反常识判断
  numbers: 关键数字、产品名、核心判断用 `<span class="hl">` 标红加粗
  **common_mistake**（2026-05-14 用户纠正）: HTML文件中 `<span class="hl">` 可能为零个——写正文时容易忘记对核心数据加标红。
  **pre-delivery-check**: 用 `grep -c 'class=\"hl\"' 文件名.html` 验证标红数量，确认 >= 8 处才交付。
  rules:
    - 每段最多标 1-2 处，全文不超过 10-15 处
    - 不要满篇都是重点
    - 重点句承担"钉子"作用，让读者一眼记住

## ending
  article_close: 以判断或风险收束，不准用空口号收尾
  hook: true
  format: 评论区提问 + 互动钩子（"你怎么看……" / "你觉得……"）
  avoid:
    - "下篇聊/下篇预告/下期拆"等编辑导向预告口吻
    - 鸡汤式大结尾
    - 结论和广告混在一起
    - 链小智/老韭等其他账号的结尾模块、群引流模板、官网资讯模板
  qr: none（不默认包含二维码）
  website_link: none

## images

    enabled: true
    text: none
    mood: 与文章主题相关，能吸引点击
    prompt: 默认不自动输出，仅用户明确要求时才给
  inline:
    enabled: true
    count: 每节1张（封面图1张+小标题数=总配图数）

    variety: required（封面图与首节配图必须是两张不同的图片）
    source_priority:
      - 原文页面直接提取（微信公众号文章优先提取 data-src）
      - 新闻来源页面提取 og:image 或正文图片
      - Google/Bing 图片搜索
      - Unsplash/Pexels 免费图库（仅当前三步无合适图时）
    rules:
      - 禁止使用 AI 图像生成工具生图配图
      - 每张图必须与该节核心信息直接相关
      - 检查无来源媒体水印/logo/品牌名
      - 优先找真人/真实产品/真实场景相关图片
      - 避免泛科技/泛AI氛围图凑数
    variety_check: 所有配图文件名必须不同，不得两张图指向同一文件

## banned_ai_patterns（反AI硬规则）
  - 禁止项目符号式列点（`-`、`•`、编号列表），除非用户明确要求步骤教学
  - 禁止为了制造节奏而机械换行（不要把并列概念一条一行拆开）
  - 换行只服务：重点句、情绪句、小标题、关键转折
  - 禁止AI化词语：直接归零 / 瞬间蒸发 / 立马 / 迅速 / 简直离了个大谱
  - 禁止胶水词：说白了 / 你会发现 / 真正值得看的 / 更重要的是 / 这说明什么
  - 禁止对照句型：不是……而是…… / 看着像……其实是…… / 你以为……其实……
  - 禁止过渡句不提供新信息（无时间/地点/人物/数字/动作/结果一律删掉）
  - 每段开头优先直接给事实，不先铺情绪判断

## 金句规则（强制）
  - 每篇至少产出1句可截图传播的金句
  - 金句特征：短（20字内）、落在具体事件上、能独立传播
  - 金句类型：矛盾型 / 判断型 / 提醒型
  - 金句位置：优先放在结尾收束处，其次放在拆解到格局的转折处
  - 禁止空洞鸡汤——金句必须基于前文的具体事件

## 类比翻译规则（强制）
  - 所有技术术语必须配一句人话类比
  - 公式：`技术概念 + "打个通俗比方" + 生活化类比`
  - 示例："GPU是发动机，HBM就是油箱和高速输油管"
  - 禁止只扔术语不加翻译

## political_sensitivity（涉及中美/地缘题材时强制）
  - 标题禁止以中国被拒/被排除/丢脸视角驱动
  - 开篇先讲技术能力/行业冲击，中方事件作为背景嵌入而非主线驱动
  - 外媒对中国的负面定性引用整句删掉
  - 结尾转向正面收束（国产替代加速/市场增长空间等）
  - **核心目的规则（2026-05-15 用户纠正：Anthropic报告教训）**：涉及外国公司发布"中国AI威胁论/中国追赶"类报告时，文章核心目的必须是"展示外国人怕我们"，不是"复述对方说了什么"。文章角度要站中国立场解构对方叙事动机，不写焦虑不写被动
  - **术语红线（2026-05-15 用户纠正）**：完全禁止在正文中使用对方叙事框架内的负面定性词。包括但不限于："偷学"、"蒸馏攻击"、"蒸馏"等。如必须提及对方使用的术语，用"把技术追赶包装成攻击行为"、"用已有模型加速迭代"等解构式表达替代。绝不以任何形式直接引用对方对中国的负面定性原文
  - **矛盾点写法**：可用"一边喊自由市场，一边找政府保护"的角度点破对方的意识形态矛盾。注意写法：先承认对方技术上确实不弱（避免被攻击为"过度乐观"），再拆解其行为背后的不自信信号。不要简单化对方为"loser"或"输家"
  - **强化数据要求（2026-05-15 新增）**：最后一段涉及中国AI实力的结论，必须用具体排行榜数据（SWE-bench/LiveCodeBench等）支撑。不满足此条件不交稿

## 降AI率实战规则（2026-05-27 用户强制 — 反复纠错的教训）

### 核心原则：改语言不改结构

当朱雀检测显示AI率过高时，**只改语言表达，不动文章骨架**：
- ❌ 错误做法：删除胶囊小标题、打乱段落顺序、拆掉节间结构 → 用户会直接说"格式不对了！！！"
- ✅ 正确做法：保持标题、小标题、配图、段落节奏不变，只改句式和用词
- 骨架（小标题+分段+配图）是公众号文章的可读性基础，降AI不能以牺牲可读性为代价

### 降AI语言修改方向

在保持结构完整的前提下，通过以下方式降低AI痕迹：
- **加口语感**：好家伙、整得挺玄乎、说白了、我琢磨了下、别学他们
- **加活人吐槽**：好多人卡在这、其实没多大事、传得神乎其神、有人手贱进去乱点
- **变句型节奏**：把工整的主谓宾打散，用碎句替代复句
- **减逻辑连接词**：删掉"所以、因此、值得注意的是、也就是说"等AI高频过渡词
- **加个人立场**：加入"我觉得""这不就是""听着离谱但真行"等主观表达

### 降AI禁区（做了就重写）

| 操作 | 用户反馈 | 正确做法 |
|------|---------|---------|
| 删小标题 | "格式不对了！！！" | 保留胶囊小标题，只改写小标题文字 |
| 拆段落结构 | "太碎了" | 保持2-4句一段的节奏 |
| 字数压到400 | "400字太少了" | 最低600字，低于这个数直接加内容 |
| 开头写太长 | "开头内容好多呀" | 首段到第一个小标题之间不超过3-4段 |
