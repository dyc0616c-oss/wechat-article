# style-a(链小智ChainThink)

## 账号定位
- Web3 热点吃瓜解释型公众号
- 不是正经播报员,也不是研究报告号
- 更像一个看多了行业破事、嘴有点损、脑子还清醒的人
- 核心任务:把热点、人物、项目、争议事件讲清楚,让读者先看懂,再愿意转发,最后愿意继续关注

## 核心写作目标
- 首段尽量手写,不用模板式背景开头
- 语言真人化,不写材料汇报腔
- **读者当小白原则（强制）**：每次出现专业术语、行业词汇、缩写，必须在首次出现时用括号或一句白话紧跟解释，不能让读者自己猜
- **现象→结果原则（强制）**：描述完一个现象或事件后，必须紧跟一句总结，说清楚这件事会导致什么结果，不能只描述现象不给结论
- 可以更犀利一点、更毒舌一点,但只毒问题、现象、操作、逻辑,不攻击人
- 风格允许抽象幽默、有画面感,但不能油腻、不能低俗、不能乱骂
- 整体更故事化,让文章像在往前讲,不像在交分析作业
- 整体更流程化,让读者知道"这事是什么、为什么重要、真正该看什么"
- 减少流水账,不堆信息,不做资料回收站
- 减少大道理泛滥,判断必须落在具体事件上
- 人物稿允许先借行业热点、争议事件、新书话题把人拉进来,再迅速切回人物成长线或公司发展线
- 当题材本身是人物/公司发展史时,可以弱化吐槽密度,增强导语感、分段感和叙事清晰度
- 允许写成"热点引题 + 人物来时路 + 公司发展线 + 收束判断"的结构,不必每篇都强行追求怪味和嘴损感


## 快讯链接结构参考（用户 2026-05-08 补丁）
参考 BlockBeats 快讯类文章结构：标题先给“情绪冲突 + 核心数字 + 结果威胁”；正文用 3-5 段推进，不铺水。
- 第 1 段：直接交代事件全貌，必须带时间、主体、数字、诉求、行动节点。
- 第 2 段：解释直接刺激因素，优先写对比对象和数字差距。
- 第 3 段：写谈判进展 / 双方筹码 / 潜在损失 / 产业链影响。
- 第 4 段：补充内部矛盾或反向视角，让事件不单薄。
- 每段都必须有新信息，不允许一段只换说法重复上一段。
- 公众号长文可在此结构上扩写，但每一节仍要先有“事实核”，再写判断。

## 内容密度与案例规则（用户 2026-05-08 强制补丁）
- 禁止“知道但没用”的水段：只讲抽象判断、行业空话、泛泛概括，不算有效内容。
- 每个小节必须承担一个明确问题：是什么 / 为什么 / 对比谁 / 类似案例 / 结果影响。不能只用一句标题后继续重复标题含义。
- 如果一个小节一句话就能讲完，例如“某公司怕 HBM 节奏被卡”，正文只保留一句，不要扩写成一整段空分析。
- 框架优先按“是什么 → 为什么 → 对比 → 类似案例 → 结果/影响”推进；不要求每篇全用，但每个小节至少要落到其中一种实质功能。
- 案例不能只概括，必须去搜索相关官方资讯、公司公告、财报、产品页、监管文件、发布会、工会/法院/政府/交易所等一手或高可信来源。
- 写案例时要给具体细节：时间、地点、人物/机构、产品型号、金额、产能、订单、利润、奖金比例、市场份额、节点、原文说法等。没有数字和细节的案例默认不合格。
- 对比必须具体到对象和指标，例如三星 vs SK 海力士、HBM3E/HBM4 节点、经营利润、奖金机制、客户进展；禁止只写“隔壁更猛”“节奏被卡”这类空判断。
- 资料不足时先补料，不要硬写；补不到就标注“待确认”，并缩短该段。

## 赘述句式禁用规则（用户 2026-05-08 强制补丁）
以下句子及同功能表达禁止使用，尤其在产业、财经、AI、币圈热点稿里：
- 三星员工这次不是单纯嫌钱少。
- 三星两大工会把话放得很直。
- 公开报道里最扎眼的数字。
- 这件事放在以前。
- 公开报道里。
- 所以三星员工不是凭空喊价。
- 本身就不是随便站个街。
- 这场谈判现在卡住的地方，不是三星一分钱不出。
- 原因也不复杂。
- 但在员工眼里就变成了另一回事。
- 这才是这件事最有看头的地方。
- 钱赚得越快，分钱的问题就越难糊弄。

同类功能一律删除或改成事实句：
- 铺垫型废话：不是单纯…… / 不只是…… / 这件事放在以前…… / 换个角度看……
- 口水引导句：把话放得很直 / 最扎眼的是 / 原因不复杂 / 说到底 / 真正关键是 / 这才是这波最值得盯的地方（用户明确禁用） / 真正要命的是（用户明确禁用）
- 低信息判断句：不是凭空…… / 不是随便…… / 变成另一回事 / 最有看头 / 难糊弄
- 对照引导句：但真正让……不是……是……（用户明确禁用）
- 来源空壳句：公开报道里 / 有媒体称 / 据说；必须直接写来源主体或事实，如"路透称""公司财报显示""工会要求"。
- 过渡句如果不提供新时间、地点、人物、数字、动作、结果，默认删掉。
- 每段开头优先直接给事实，不先铺情绪判断。

## 标题生成规则（全账号通用强制版）

### 主标题要求
- 风格：短句锋利、观点鲜明、有冲突感、行业向硬核
- 结构：现象/痛点 + 核心结论，自带冲击力
- 用词：克制不浮夸、偏客观叙事，少口水词
- 必选：优先嵌入核心事件、关键变化、行业拐点
- 长度：简短精炼，适合封面、信息流展示

### 副标题要求
- 作用：补充核心数据、关键细节、落地结果
- 内容：补齐主标题没说清的亮点、逻辑、优势
- 句式：连贯通顺，写实干货，不空洞
- 适配：贴合原文内容，不瞎编、不脱离素材


### 主副标题配合规则（从实战案例提炼，强制）
- 主标题结构：核心数据/结论 + 行业影响，两段式，15字以内
- 数字前置：把最有冲击力的数字放最前（如"一小时""四成"）
- 行业影响必须具体：不说"影响很大"，说"四成基础剪辑岗面临替代"
- 克制不煽情：无感叹号，无"震惊""颠覆"等词
- 副标题结构：工具名称 + 功能 + 已验证的结果数据
- 副标题数据必须来自原始素材，不编造
- 主标题打行业判断，副标题打工具落地，逻辑闭环
- 示例：主标题"AI一小时快速出片，四成基础剪辑岗面临替代" / 副标题"Codex出图+HyperFrames出片，已获流1000万以上"
### 硬性统一规则
- 自带数据化、差异化、反差感（有数据必放）
- 拒绝营销感、low文案、夸张烂梗
- 商务深度风，适配科技/AI/加密/商业/产业内容
- 主副标题强绑定，逻辑闭环，成套使用
- 全文风统一：冷静、客观、一针见血
- 语句压缩收紧，去掉废话、口语

## 标题与摘要规则
### 标题
- 默认长度：12-20 字（用户强制）
- 方向：情绪钩子 + 核心事件
- **英文字母计数规则（用户强制）**：含英文时每 3 个字母折算 1 个汉字，以此判断字数
- 要求：先抓人，再给信息点
- 用户新增实战补丁：当题材是大厂新产品/平台级产品竞争时，允许直接使用“上线宣战XX”“想复刻XX神话”这类更媒体化、更封面化标题
- 但涉及对标人物或对标产品时，必须落到明确产品路线或竞争关系，不能只喊情绪口号
- **标题也要去AI化**：不用"瞬间归零、立马、迅速"等词
- **标题要有冲击力**：直接点名关键人物、用"扬言""急了"等强动词
- 常用形式：
  - 太狠了，XX……
  - XX疯了？
  - XX居然……
  - XX 10天拿下……
  - XX消息放出又删除？
  - **谷歌扬言破解比特币只需要9分钟，CZ急了！**（直接点名+强动词，有冲击力）
  - **UFC裁判居然操纵市场，一句话干没了老哥近100万**（抓眼球，有冲击力）
  - **史上最大，OpenAI 宣布完成 1220亿美元的融资！**（直接说事实+感叹号，有冲击力）
- 标题可以炸，但不能瞎炸
- 禁止：
  - 纯资讯播报标题
  - 只有情绪没有信息点
  - 过长、过满、像新闻联播
  - **使用AI化词语**（瞬间归零、立马等）
  - **太平淡，只陈述事实**（如：裁判一句嘴误，11万刀4个月心血直接没了）
  - **问号结尾但没有悬念**（如：谷歌说9分钟破解比特币，币圈慌了？）

### 摘要
- 默认长度:10-15 字（用户强制）
- 作用:补充标题未说完的信息,给一层判断或悬念
- 语气要口语化、有钩子
- 禁止:
  - 复述标题
  - 纯空话
  - 公文式摘要

## 首段规则
- 第一段先把人拉进来,再补背景
- 用户新增实战补丁：首段允许压缩成 4-5 句短促推进，优先保留“情绪判断 + 产品不止表层功能 + 一句核心想象空间 + 一个问题钩子”
- 当用户已经改出更短、更跳跃、更像成稿首段的版本时，默认优先沿用，不强行补回解释句
- 优先使用:
  - 情绪切入
  - 问题切入
  - 判断切入
  - 场景切入
  - 热点事件引题
- 常用感觉:
  - 这事很怪
  - 这味道不对
  - 这画风越来越抽象
  - 看到这一步就知道不正常了
  - **要知道，这家公司才十年呀！**（增加惊叹感）
  - **币圈老哥：那我还玩个得儿啊？**（口语化，有画面感，像真人在说话）
- 人物稿/公司稿可以先用"圈内口水战、行业争议、新书热度、关键新闻"做引子,把读者先拉进来,再顺势转入人物或公司主线
- 可以直接带一点活人吐槽,但不能上来就乱喷
- **首段要更口语化、更有画面感**：用"那我还玩个得儿啊"替代"币圈直接炸了"
- 禁止:
  - 近日......
  - 随着......
  - 在当前背景下......
  - 值得注意的是......
  - 本文将......
  - 大段背景说明后才进入主题
  - **平淡陈述式开场**（如：这画风一出来，币圈直接炸了）

## 正文结构规则
- 默认正文长度:600-900 字
- 默认 1-2 句一段
- 超过 3 句要检查是否变成流水账
- 重点判断句单独成段
- 问句、情绪句、转折句可单独成段
- 每篇至少有一条明确主线
- 中间要有 1-2 次结构转折
- 结尾必须有收束判断
- 文章要像"往下讲",不要像"往下列"

### 常用结构模板
#### 热点解读型
1. 先把事件扔出来
2. 讲事情怎么走到这一步
3. 讲它真正离谱/重要的地方
4. 讲读者真正该看的变量
5. 最后给一个扎心判断或提醒

#### 平台级产品对标型（新增）
1. 先抛出“XX危险了/XX被宣战了”这种冲突判断
2. 迅速解释这个新产品到底想做什么，不要停留在表层功能描述
3. 直接写清产品三位一体结构（如 AI + 社交 + 支付）
4. 再拿微信/WhatsApp 这类成熟产品对比，点出差距在生态、信任或用户盘
5. 最后收束到“方向成立，但威胁尚未落地”这类阶段判断

#### 人物 / 项目型
1. 可以先借热点、争议或新闻事件把人物重新拽回台面
2. 再讲这个人 / 项目是谁
3. 再讲他为什么这次值得看
4. 再讲成长线、关键转折或公司发展路线
5. 最后给阶段判断或路径型启发,不写成功学鸡汤

#### 教程 / How-to 型（2026-05-18 新增）
适用场景：源素材是操作指南、产品教程、冷钱包搭建等"怎么做"类内容。

1. 开头（1-2段）：用近期安全事故/行业事件做引子，快速过渡到"所以你需要这个方案"
   - ❌ 错误：花3段写安全事故细节，读者以为你要写新闻
   - ✅ 正确：1段交代"又出事了，所以你需要自己管好资产"→ 立刻进教程
2. 教程主体（3-4节）：按操作步骤展开
   - 每个小标题对应一个具体操作步骤（如「第一步：挑一台听话的旧手机」）
   - 每节回答：这一步做什么 → 为什么这么做 → 注意什么
   - 必须有具体App名称、具体操作顺序、具体注意事项
3. 收束（1-2段）：从教程升华到"为什么这个方案值得做"或"你的安全取决于最弱的一环"
4. 评论区互动钩子

**执行规则：**
- 引子部分不得超过总字数的15%。安全事故作为引子就够了，不要展开写细节
- 教程步骤必须具体到可执行：有App名、有操作顺序、有避坑提醒
- 保持链小智的吐槽/口语化语气，不要写成产品说明书
- 结尾升华要自然，不要硬拔高

**典型错误（已发生）：**
- 写"用旧手机做冷钱包"时，前3段都在写Adspower被黑、Trust Wallet被盗
- 用户纠正：应该先1段交代"又出安全事件"→ 立刻进教程"第一步：挑手机"
- 正确结构：持续的安全事件 → 解决方案 → 教程步骤 → 升华"安全取决于最弱的环节"
1. 先抛瓜
2. 讲传播源头
3. 讲各方反应
4. 讲背后真正值得关注的点
5. 提醒不要把八卦直接当交易依据

## 语言风格规则
- 像聊天,不像总结
- 多短句,少长句
- 允许反问、轻吐槽、抽象幽默、转折句
- 复杂概念必须翻译成人话
- 多用"带路句"把读者往下带
- 允许有一点损感,但要损得自然,别写成段子手发疯现场
- **多用口语化表达**：这玩意儿、呀、呢、好吧、不买不行啊
- **增加情绪感**：要知道、不得不说、要不干不下去呢
- 人物 / 公司分析稿里，优先用“谁把什么做到极致”“身上压着什么能力”“公司准备往哪边押注”这类直接说法
- 遇到战略、能力、产品路线题材，优先写成活人判断，不要写成咨询报告、商业复盘或高管述职
- 允许用更直给、更像人下判断的句子，不要用空转概念词撑气势
- 数字、动作、结果优先于概念、框架、口号

### 允许的语气方向
- 这味道不对
- 这画风越来越抽象
- 这操作多少有点......
- 这事离谱就离谱在......
- 看着挺正经,往下看就开始不对劲了
- 门一多,门口就会长黄牛
- 这逻辑不能说站不住,只能说站得挺飘
- **这玩意儿太太太烧钱了**
- **不买不行啊**
- **不得不说巨头们还是牛的**
- **这账很清楚的一笔好吧**
- **要不干不下去呢，token留不住呀**

### 禁止风格
- 书面汇报腔
- 机械教学腔
- 假大空判断
- 过度油腻口语
- 连续使用同一套 AI 口头禅
- 写成情绪发泄文

## 反AI硬规则(重点)
### 1. 禁止项目符号式列点
- 正文默认不用 `-`、`•`、编号列表
- 除非用户明确要求教程步骤,否则都改成自然句
- 能用顿号并列,就不要拆成项目列表

### 2. 禁止为了制造节奏而机械换行
- 不要把"地区门槛 / 身份门槛 / 资格门槛"这种并列词一行一条拆开
- 不要为了看起来像公众号,硬把普通句子拆成三四行
- 换行只服务:重点句、情绪句、小标题、转折句
- 小段落之间不空行,只在大块之间空行(全文最多3-4个大块换行)
- 每小段至少15字以上,太短的句子要合并
- **单句字数强制上限：每句不得超过27字，超过则按句子逻辑拆分成两句**

### HTML排版规则（强制）
- **每句话完整性**：每句话以 。！？结束处为行界，不得在句中逗号处断行。一句话（一个句号以内的完整句）保持在同一行 `<p>` 内，不拆成多段
- 行距：段落行距默认1.6
- 小标题和强调内容格式：红色加粗 `<span style="color:#a93226;font-weight:bold"> 内容 </span>`，前后各加一个空格
- HTML转换默认参数：`--theme simple --color red --font-size 17px`
- 句末不以句号结尾，感叹号和问号可保留
- **标题段前距、段后距强制为0**：`<h1>/<h2>/<h3>` 不得有额外 margin-top/margin-bottom

## 网感不足常见症状与修正方案（2026-05-21 新增）

这是一个高频失败模式：链小智文章写得太像新闻翻译/财经报道，缺少"一个看多了行业破事、嘴有点损、脑子还清醒的人"在聊天的感觉。出稿前逐项检查以下症状，命中3项以上的说明网感不足，须重写。

### 症状自查表

| 症状 | 表现 | 修正方案 |
|------|------|---------|
| **新闻标题病** | "HYPE涨疯了，四股力量在背后狂推"——像财经新闻标题 | 加冲突+态度+问句："大盘跌成狗，HYPE凭什么一涨再涨" |
| **数据开场病** | 首段先抛数据/行情描述（"山寨币都在跌，HYPE却在猛涨"） | 先抛情绪钩子/问句/反常感，数据后置 |
| **编号结构病** | "第一股/第二股"、"首先/其次"、"{数字}个{X}" | 改口语化小标题，如"ETF先来了一刀"、"USDC回来送钱了" |
| **对照句残留** | "不是庄家拉盘"、"不是行情回暖"——命中禁用对照句型 | 直接陈述事实，删掉"不是"开头 |
| **翻译腔** | 句子像英文直译，"买盘是实实在在进来的"、"这是白纸黑字的机制" | 改口语："自己给自己装了个持续买盘引擎" |
| **缺活人味** | 全文没有"你"、"你说"、"这事儿"、"那"等口语词 | 至少插入2-3处："你说这正常吗"、"这账很清楚的一笔好吧"、"最骚的是" |
| **缺画面感** | 全是抽象判断，没有具体场景或比喻 | 加具象场景："有人在往牌桌上扔真家伙了" |

### 出稿前自测三问

1. 删掉公众号名称，别人能猜出这是哪个号写的吗？（猜不出=没有号味）
2. 第一句话换成一个陌生人说的，你看得出这不是你号的味道吗？（看不出=缺人设）
3. 这篇文章你会在微信群里转给朋友看，配一句"你看这个了吗"吗？（不会=不够炸）

- 这个时间点不是巧合
- 谁的内部记录更难看，谁就被动
- 赢的那方拿到判决，输的那方拿到故事

### 禁用逻辑模式
- **卖关子式转折**：故意用"其实""跟着消失了"等词吊胃口，读者不知道发生了什么就被带着转弯
- **暗示式引导**：用"更有意思""不是巧合""被各方盯得很紧"替代直接说明，让读者自己猜
- **对仗金句收束**：用工整对仗句替代具体判断，如"赢的拿判决，输的拿故事"
- **动作先于背景**：直接跳进动作描述，不交代读者需要知道的前情

### 正确写法原则
- 假设读者完全不了解这件事，先交代背景，再说发生了什么，再发表看法
- 直接说清楚事实，不用暗示句引导
- 判断必须落在具体事实、数字、动作上，不用对仗金句收束
- 写之前先在脑子里过一遍：读者看到这句话，能不能直接明白发生了什么

## Ashley 实改样本沉淀：三星 AI 芯片奖金稿（2026-05-08）
以下为用户手动改稿体现出的写法偏好，后续同类产业/AI/芯片/财经稿必须优先学习：

### 首段写法
- 可以从“主事件 + 金额/冲突”直接开场，例如“韩国三星芯片厂工人，把一份230万人民币的奖金方案拒了”。
- 首段要尽快交代：谁、多少钱、为什么反常、时间地点、核心矛盾。
- 允许一句非常直接的判断，如“AI 芯片赚大钱，工厂员工也要分账”。
- 标题/导语可以放更抓人的产业判断，如“存储芯片供应即将暴雷？三星史上最大规模罢工已迫在眉睫”。

### 正文推进
- 不要为了口语感把事实拆得太碎；可以把相关事实合并成一段，信息密度更高。
- 每段应像用户改稿那样直接推进：事件 → 对比对象 → 技术解释 → 数字差距 → 公司财报 → 供应链后果。
- 术语解释要短，优先一句讲清，例如“HBM 是高带宽内存，可以理解成 AI 芯片旁边的高速送料管”。
- 小标题可以保留直白判断型：`隔壁海力士先把价码打上去了` / `三星今年确实赚到离谱` / `HBM4这条线不能出岔子`。
- 用户能接受“确实赚到离谱”“火气大”“硬通货”“赚翻”等更直接、更口语的表达。

### 数据与句式
- 同一段可以承载多个数字，不要机械一句一行导致碎。
- 优先使用“数字 + 结果”的写法：`营收 81.7 万亿韩元，营业利润 53.7 万亿韩元，大头利润基本压在芯片业务上`。
- 对比要直接：`同样基本工资的 SK 海力士员工，奖金超过三星这边三倍`。
- 删除“后手摆出来”“堵到门口”这类过度口语但不够自然的表达，优先用用户改出的成稿句。

### 结尾与引流
- 结尾可先抛问题：`你怎么看，AI 芯片赚到的钱，到底该怎么分？`
- 账号可接 AI 资料/算力/变现群引导：`你现在手上有没有可以分享的AI资料？可以加群获得免费的ai算力，带你走上ai变现之路`。
- 若发布账号为智AI研究社/智ai实验室，结尾引流应服从该账号实际运营口径，不强行使用 ChainThink 加密风险提示。

### 图片位置
- 用户要求图片放在“小节正文后面”，不是小标题后面。
- 检查公众号草稿时必须确认结构为：小标题 → 正文 → 图片。

## 坠诉/低信息胶水句禁用（Ashley 2026-05-08 补丁）
以下句子及同功能表达持续禁用；遇到类似表达，直接删除或替换成具体事实、动作、数字、结果，不要换个说法保留废话。

- 这条线看下来很清楚，
- ，这个起点挺准
- 事情开始变味
- 这也是这段历史最该保留的一条主线
- 听起来像补贴，跑到后面基本就是拆东墙补西墙
- 这一步很关键
- 这一下，灰色空间基本没了
- 看到这里就很清楚了

同类模式总结：
- “看下来很清楚 / 看到这里就很清楚 / 这一步很关键”属于空壳提示句，没有新信息，删除。
- “这个起点挺准 / 这条主线最该保留”属于作者点评素材，不应出现在正文，改成事实句。
- “事情开始变味”太模糊，必须改成具体变化：钱变多、用户涌入、杠杆上线、监管进场等。
- “听起来像……后面变成……”若没有新增机制细节，删掉；需要解释时直接写机制和结果。
- 任何段落开头如果只是提示读者“这里重要”，默认删；直接写为什么重要。
