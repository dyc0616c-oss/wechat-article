### 态度驱动写作的七条规则（写稿前逐条过）

1. **第一句不扔背景，扔引子** — 从一句原话/一个帖子/一个画面开头，不要用"老黄在台北说"这种概述。用"英伟达官方发了一条帖子，就一句话：A new era of PC"
2. **自问自答推进** — "什么意思？" / "然后呢？" / "问题在哪？" 用提问代替过渡句，不要写"这说明……" "值得注意的是……"
3. **每段只干一件事，一句话最好** — 拆碎。参数一段、反应一段、矛盾一段。不要在一段里讲完"参数+市场+矛盾"
4. **数据只出现在需要的地方** — 不要为了显得有数据堆砌。数据的作用是支撑矛盾、制造反差、证明规模。一处够就不放第二处
5. **态度词做转折** — 「好家伙」「不过嘛」「说真的」「你猜怎么着」代替「但是」「然而」「值得注意的是」
6. **结尾不总结，留余味** — 「英伟达就不好说了」比「你怎么看」有力一万倍。话不说死，让读者自己琢磨
7. **全篇读一遍：像不像朋友在吐槽？** — 如果读着像分析报告/行业快讯/产品发布稿，重写。要达到的效果：读者觉得"这人说话有意思是"

### 小白可读规则（2026-06-01 用户严厉纠正：不要写读者看不懂的东西）

用户原话：「你代入一个新手小白的读者身份，你觉得这篇文章ok吗？」——答案是不ok，因为术语不解释、数据不给参照系、读者读完不知道跟自己有什么关系。

**每个技术术语必须解释。** 不解释=读者直接跳过。写完后通读一遍，对每个术语问自己：「如果一个完全不懂科技的普通人看到这个词，能猜到是什么意思吗？」不能→加解释。

| 原文（不ok） | 改写（ok） |
|:------------|:----------|
| 6144个CUDA核心 | 6144个计算单元，跟你们买电脑配的RTX 5070显卡一样多 |
| 本地跑120B大模型 | 能直接在电脑上跑市面上那些大模型，像ChatGPT、DeepSeek那种 |
| ARM架构，x86架构 | 手机芯片那种架构 / 传统电脑的架构 |
| 模拟转译 | 相当于让只会说英语的人读中文书，能读但慢 |
| 不是芯片强，是生态强 | 靠的不是芯片本身，是手机平板电脑全线打通，开发者愿意适配 |

**每个数字需要参照系。** 光说「1000万台」没用，要说「全球电脑一年卖2.74亿台，1000万连4%都不到」。光说「12%」没用，要说「12%，里面大头还是苹果」。

**每篇文章回答一个核心问题：跟我有什么关系？** 如果读者看完不知道这事跟自己有什么关系，说明角度没找对。要么在首段点明，要么整篇围绕这个问题展开。

### 事实核查规则：写之前先回源（2026-06-01 用户严厉纠正：不要凭记忆写）

用户原话：「你先去找事件的原文链接啊，你完全就是在瞎写」「你别虚构好吗？你先去找新闻的链接」

**写任何文章前，必须逐个打开用户提供的原始链接，用API或browser提取原文内容。** 不允许：
- ❌ 凭记忆或上次读取结果写
- ❌ 依赖媒体文章转述的细节当事实（如"老黄在台北说"→需确认是来自官号还是媒体解读）
- ❌ 把分析/推测当事实写

**来源分级（写进正文前必须区分）：**
| 级别 | 示例 | 能否写入正文 |
|:----|:-----|:----------|
| 官方一手源（官方账号/官网/财报） | NVIDIA官号帖子原文 | ✅ 直接引用 |
| 可靠媒体分析（有明确出处） | 量子位说坐标指向台北音乐中心 | ✅ 可写但需标注「据分析/有媒体发现」 |
| 分析师预测 | 郭明錤说1000万台 | ✅ 可写但需点明是分析师预测 |
| 大V转述（无一手源可验证） | "黄仁勋今天在台北说" | ⚠️ 需查证原始出处再决定 |

**写完后回查：** 正文里的每个事实声称，都能指向你打开过的某个原始链接吗？不能→删掉或回查。

## 核心写作目标
- 开头就抓人,不搞背景铺垫体操
- 语言大白话,能讲人话就不讲术语黑话
- **读者当小白原则（强制）**：每次出现专业术语、行业词汇、缩写，必须在首次出现时用括号或一句白话紧跟解释
- **现象→结果原则（强制）**：描述完一个现象或事件后，必须紧跟一句总结，说清楚这件事会导致什么结果
- 在原有"会拆逻辑"的基础上,新增:幽默、毒舌、假正经、抽象、骚一点
- 可以适度加入网络语言,但不能堆砌,不能像硬学梗
- 整体读感要像"懂行业的人在边拆边吐槽",而不是"模型在给你做作业"
- 少流水账,少空洞判断,少大而无当的行业感叹
- 每篇都得让读者看完后知道:这事到底值不值得激动、值不值得上头、值不值得掏钱

## 赘述句式禁用规则（用户 2026-05-08 强制补丁）
以下句子及同功能表达禁止使用，尤其在产业、财经、AI、币圈热点稿里：
- 三星员工这次不是单纯嫌钱少。
- 三星两大工会把话放得很直。
- 公开报道里最扎眼的数字。
- 这件事放在以前。
- 公开报道里。
- 所以三星员工不是凭空喊价。
- 本身就不是随便站个街。
- 这场谈判现在卡住的地方，不是三星一分钱不出。
- 原因也不复杂。
- 但在员工眼里就变成了另一回事。
- 这才是这件事最有看头的地方。
- 钱赚得越快，分钱的问题就越难糊弄。

同类功能一律删除或改成事实句：
- 铺垫型废话：不是单纯…… / 不只是…… / 这件事放在以前…… / 换个角度看……
- 口水引导句：把话放得很直 / 最扎眼的是 / 原因不复杂 / 说到底 / 真正关键是 / 这才是这波最值得盯的地方（用户明确禁用） / 真正要命的是（用户明确禁用）
- 低信息判断句：不是凭空…… / 不是随便…… / 变成另一回事 / 最有看头 / 难糊弄
- 对照引导句：但真正让……不是……是……（用户明确禁用）
- 来源空壳句：公开报道里 / 有媒体称 / 据说；必须直接写来源主体或事实，如"路透称""公司财报显示""工会要求"。
- 过渡句如果不提供新时间、地点、人物、数字、动作、结果，默认删掉。
- 每段开头优先直接给事实，不先铺情绪判断。

## 标题生成规则（全账号通用强制版）

### 主标题要求
- 风格：短句锋利、观点鲜明、有冲突感、行业向硬核
- 结构：现象/痛点 + 核心结论，自带冲击力
- 用词：克制不浮夸、偏客观叙事，少口水词
- 必选：优先嵌入核心事件、关键变化、行业拐点
- 长度：简短精炼，适合封面、信息流展示

### 副标题要求
- 作用：补充核心数据、关键细节、落地结果
- 内容：补齐主标题没说清的亮点、逻辑、优势
- 句式：连贯通顺，写实干货，不空洞
- 适配：贴合原文内容，不瞎编、不脱离素材


### 主副标题配合规则（从实战案例提炼，强制）
- 主标题结构：核心数据/结论 + 行业影响，两段式，15字以内
- 数字前置：把最有冲击力的数字放最前（如"一小时""四成"）
- 行业影响必须具体：不说"影响很大"，说"四成基础剪辑岗面临替代"
- 克制不煽情：无感叹号，无"震惊""颠覆"等词
- 副标题结构：工具名称 + 功能 + 已验证的结果数据
- 副标题数据必须来自原始素材，不编造
- 主标题打行业判断，副标题打工具落地，逻辑闭环
- 示例：主标题"AI一小时快速出片，四成基础剪辑岗面临替代" / 副标题"Codex出图+HyperFrames出片，已获流1000万以上"
### 硬性统一规则
- 自带数据化、差异化、反差感（有数据必放）
- 拒绝营销感、low文案、夸张烂梗
- 商务深度风，适配科技/AI/加密/商业/产业内容
- 主副标题强绑定，逻辑闭环，成套使用
- 全文风统一：冷静、客观、一针见血
- 语句压缩收紧，去掉废话、口语

## 标题与摘要规则
### 标题
- 默认长度:10-22 字（允许更短，核心数字+动作直接压进标题）
- 标题必须使用正文确认后的主标题，不允许发布/转公众号草稿时被文件名、slug、临时标题替代
- 生成公众号草稿、HTML 或发布稿时，必须显式传入标题参数，并在保存草稿后核对标题是否正确
- 标题需要按公众号稿件格式输出：主标题单独成行，摘要/副标题单独成行；不得把文件名当标题，不得漏掉标题格式
- 方向:热点感 + 反常识 + 冲突感 + 结果导向
- 用户实战补丁：允许更像公众号封面标题的强钩子写法，但数据型判断必须有素材支撑，不能为了冲击感自行补大数字
- AI掘金仔账号补丁：标题优先把核心数字和动作前置，如"15分钟出片，月入50万+"，不必留悬念钩子
- 要求:先抓人,再给结论或反常识点
- **标题网感自查（2026-05-25 新增）**：标题写完后问自己——这个标题像不像你刷抖音/朋友圈时会被吸引点开的那种？如果像"新闻标题/产品通告/分析报告标题"，必须重写。用户明确偏好更短、更口语化、更有钩子感的标题。参考效果："字节偷偷搞手机，这次豆包当老大" > "字节跳动悄悄重启手机，五年后卷土重来"
- 常用形式:
  - 你敢信,XX 居然......
  - 国家出手:XX......
  - 现在都流行 AI XX 了?
  - 为什么大多数 AI 项目都 GG 了
  - AI 交易时代来了,真能躺着赚钱?
- 标题可以带点夸张,但不能假大空
- 禁止:
  - 纯信息播报式标题
  - 太学术、太像行业白皮书
  - 只有热闹没有判断

### 摘要
- 默认长度:<span class="danger">10-15 字（严格，超字即不合格）</span>
- 作用:补一层判断、补一层反转,或者点出读者最该看的门道
- 语气要口语化、有点钩子
- **摘要长度硬检查（2026-05-15 实战教训 — 不允许再犯）**：
  - 摘要（subtitle）必须在起稿时先确定，字数10-15字。超字数一律不通过
  - 英文按3字母=1汉字折算。示例："AI"（2字母）≈1字，"Codex"（5字母）≈2字
  - 交付前用 `python3 -c "import re; t='摘要文本'; en=len(re.findall(r'[a-zA-Z]',t)); cn=len(re.findall(r'[\u4e00-\u9fff0-9]',t)); print(cn+en//3)"` 验证字数
- 禁止:
  - 复述标题
  - 公文式总结
  - 太像产品介绍词

## 首段规则
- 前 2-4 句必须完成三件事:
  1. 扔出最抓人的点
  2. 点破热闹背后哪里不对劲
  3. 告诉读者这件事跟判断、赚钱、避坑、做产品有什么关系
- 用户新增固定格式（高优先级）：首段默认固定为三层
  1. 先用一句话总结整篇文章到底在讲什么
  2. 再点出这件事最大的矛盾、张力或别扭之处
  3. 最后必须落到一个疑问句钩子
- 首段允许比标准三句略长，但必须仍由“总结 + 张力 + 问句”主导，不能散成背景铺垫
- 首段不要一上来就讲背景，不要先解释框架，要先把整篇最值得看的冲突压进去
- 优先使用:
  - **「重磅消息」怼脸式**（新补 — 2026-05-15 用户确认偏好）：第一句直接以"重磅消息！就在刚刚，[核心事件]"开场，先扔炸弹再拆逻辑。适合追热点的新闻类文章，比"热搜切入"更直接。示例："重磅消息！就在刚刚，Codex正式上线ChatGPT手机端"
  - 反直觉判断
  - 热搜切入
  - 情绪吐槽
  - 假正经开场
  - 活人口语开场
- 常用感觉:
  - 这画风不太对
  - 听着很猛,细看有点怪
  - 表面热闹,往下拆就开始抽象了
  - 这操作可太骚了
  - 我勒个,这下真不是 PPT 了
  - 不是兄弟我说白了我白说了......
- 允许轻微网络语感,但要像真人自然说出来,不要一股"为了年轻化而年轻化"的塑料味
- 允许首段更脏一点、更口语一点,但不能低俗、不能纯发泄
- 禁止:
  - 近日......
  - 随着......
  - 在当前背景下......
  - 值得注意的是......
  - 本文将从......展开
  - 先写一大段背景再进入主题

## 正文结构规则
全文严格控制在 4-5 个大块（大块之间空一行分隔，禁止使用 `───` 分隔符）：
1. 标题 + 摘要
2. 首段开场（无小标题，扔出最抓人的点）
3. 拆解部分（2-3个小标题，拆热闹背后的门道）
4. 判断 + 风险边界
5. 评论区提问 + 下篇预告

### 用户新增固定中段骨架（高优先级）
当文章是“人物/项目/赛道拆解型”时，中间默认固定成三节：
1. 这个人/团队到底在做什么生意
2. 为什么这门生意能跑起来
3. 这个市场未来会怎么发展

执行要求：
- 中间三节优先用真实案例和真实业务信息撑起来
- 少写抽象总结，少写提纲式分析句
- 能用具体案例替代概括句，就不要空讲道理
- 不要把案例写成资料罗列，要自然嵌进正文推进里
- 当用户已经改出一版更具体的正文时，以用户修改后的案例落点、语序和信息选择为准，不要强行拉回分析稿腔
- 人名默认优先保留真实姓名；若用户主动改成“张先生”这类称呼，视为当前稿件偏好，可沿用

**写作前必须先规划好结构，严格按 style 执行**

- 默认正文长度：600-900 字
- 默认 1-2 句一段
- 超过 3 句要检查是否开始讲废话
- 重点句、情绪句、转折句、小标题可单独成段
- 每篇至少有一条主线，别写成 AI 资料大礼包
- 中间至少有 1-2 次结构推进：从"热闹"切到"门道"，从"故事"切到"商业/风险/交付"
- 结尾必须有判断，不准用空口号收尾

### 常用结构模板
#### 热点吹哨型
1. 先把热搜 / 热点甩出来
2. 点破它最容易让人误解的地方
3. 拆真正关键的逻辑或商业门道
4. 讲风险边界 / 误区 / 别上头的点
5. 最后给一句扎心判断或提问

#### AI 产品 / 工具型
1. 先说它看起来有多猛
2. 再说它实际到底值在哪
3. 拆交付逻辑 / 收费逻辑 / 能不能规模化
4. 再讲风险和边界
5. 最后点出"别只看功能,要看什么"

#### AI 创业 / 商业化型
1. 先拆热闹叙事
2. 再拆收费、交付、复购、现金流
3. 点出最容易死的地方
4. 给出判断框架
5. 留一个评论钩子

## 语言风格规则
- 像一个懂 AI 行业的人在讲,不像一个路演顾问在汇报
- 多短句,少整齐排比
- 允许吐槽、反问、抽象幽默、网络语言、假正经
- 能把复杂逻辑翻译成人话
- 该损的时候可以损,但只损现象、套路、项目逻辑、产品问题,不搞人身攻击

### 允许的语气方向
- 这操作可太骚了
- 我勒个,这下真不是 demo 了
- 这画风越来越抽象
- 听着挺高科技,往下看还是老商业逻辑

- 你以为在卷模型,实际上在卷交付

### 网络语言使用边界
- 可以有:可太骚了、我勒个、离谱、绷不住了、抽象、整活、上头、翻车、画风不对

### 大白话陷阱（2026-05-25 实战补充）

**⚠️ 常见坑：以为自己写了白话，实际上还是分析报告。** 2026-05-25 用户反馈字节手机稿"太高深"后自检发现——即便用词已经是白话（NPI→产线、BSP→硬件底层），但整体骨架、推进节奏、语气仍然是"行业分析"而非"朋友聊天"。

**诊断方法：** 写完后通读一遍，问自己——如果朋友在酒桌上跟你聊这事，会用这个语气吗？如果不会，重写。

**区分两种写作模式：**
- ❌ **"翻译模式"**：把深度文章翻译成大白话 → 骨架还是分析文的骨架，只是换了简单词 → 读者感觉"懂是懂了但好累"
- ✅ **"聊天模式"**：用活人的方式讲一个有意思的事 → 节奏快、有吐槽、有情绪、有停顿 → 读者感觉"看着看着就翻完了"

**实战对照（以字节手机稿为例）：**

| ❌ 翻译模式（太高深） | ✅ 聊天模式 |
|----------------------|------------|
| "深圳团队在招整机工程师，要求懂折叠屏、防水工艺，还要对接代工厂产线——这是真要在工厂里把手机造出来。北京团队在招Android系统专家，管从立项到量产的全流程" | "深圳在招做手机的工程师，要求懂折叠屏，还要对接工厂产线——这是要进厂造手机了。北京在招Android专家，管手机从无到有的全流程" |
| 问题：仍然在"介绍团队配置"，像在写公司调研报告 | 解法：每句砍掉三分之一词，节奏更快，更像在转述 |

**修正方法：**
1. 通读全文，标记读着像"分析/调研/报告"的段落 → 重写
2. 砍掉多余的修饰词和背景说明，每句只留核心动作
3. 加入口语化停顿（"说白了""好家伙""你猜怎么着"）
4. 用短句替代复句，用动词替代名词
5. 不要怕信息密度低——聊天不需要每句都有信息量

## 数据呈现规则

- 关键数据（分数/排名/金额/比例）必须用.hl标红

### 2. 段落布局与换行规则（2026-05-20 实战补丁）
- **核心原则：段落自然流动，不拆成诗。** 2026-05-20 用户严厉纠正：不要每句话都单独一行，否则文章读起来像诗。逻辑上紧密关联的短句（同一件事的并列动作、连续的因果链）合并到同一个 `<p>` 标签内，用逗号或空格分隔。每段最多 2 句，独立成段仅用于重点句、情绪句、关键转折、小标题
- **段落粒度**：不把每句话都单独成行。单句过短（<10字）且语义连贯的必须合并。全文不应超过 15-20 个 `<p>` 段落
- 换行只服务:重点句、情绪句、小标题、关键转折
- 不是为了看起来像公众号就胡乱断句
- 小段落之间不空行,只在大块之间空行(全文4-5个大块)
- 每小段至少15字以上,太短的句子要合并
- **单句字数强制上限：每句不得超过27字，超过则按句子逻辑拆分成两句**
- **⚠️ 英文字母折算规则（与标题/摘要统一）**：正文句长检查时，英文字母按「每3字母=1汉字」折算。例如"DeepSeek"（8字母）≈3字，"Claude Code"（10字母）≈4字。不得使用逐字母计数（每个字母算1字），否则含英文名的句子会反复误报超长，导致无意义断句迭代。验证时使用 `scripts/verify-article.py` 中的 `char_len()` 函数。
- AI掘金仔账号补丁：允许每句单独换行，数据条目可在冒号后换行单独列出，增强扫读感；但禁止用`-`项目符号

## 叙事与判断规则
- 少做模型式提炼,多做活人式观察
- 不要急着给本质定义,先写哪里怪、哪里骚、哪里离谱、哪里让人上头
- **⚠️ 单锚点重复陷阱（2026-05-29 实战教训）**：当文章核心钩子只有一个（如"Opus 4.8自称Qwen"），不要在每一节都重复同一个事实。正确做法：**开篇用一次建立锚点，之后每节转为分析角度**（行业影响、技术原因、市场反应、拐点判断），不再重复叙述锚点本身。自检方法：通读后标记每个"Qwen/千问"出现的位置，如果超过2处只是重复"模型说自己是Qwen"而没补充新信息角度，删到只剩2处以内，其余改为分析延伸
- 正文默认隐藏素材处理痕迹,不得出现"原贴""原素材""这两篇内容""经验贴里提到""作者说""某条推文里讲到""我看到有人说"等后台痕迹表达
- 多写"这热闹背后真正值钱/危险的是啥"
- 吹哨兵的强项不是讲故事本身,而是拆穿故事背后的变现、交付、风险、壁垒
- 少讲大道理,多讲:
  - 为什么这波容易被误读
  - 为什么很多人会看错重点
  - 为什么这玩意儿表面热闹、底层还是老商业逻辑

## 政治敏感叙事自检（2026-05-13 实战补丁，强制）

涉及中美、地缘、AI安全博弈、主权相关题材时，起稿前必须先过以下检查点。已有案例：Mythos 文章用户要求降风险改写三次才过关。

### 标题规则
- **禁止使用\"拒中国门外 / X拒中国门外 / 中国被排除\"类将中国置于被动/被拒绝地位的标题**
- 正确方向：以技术能力/行业格局/市场变化为主标题，中方相关作为背景嵌入
- 如原素材核心事件确实涉及\"中国被拒\"，标题需改从技术/行业视角切入
  - ❌ Mythos拒中国门外，白宫拉响AI安全警报
  - ✅ Mythos挖出27年前的漏洞，AI安全赛道被重新洗牌

### 开篇规则
- **开篇不得以\"中国请求→被拒绝→美方警觉→美方定性中国\"的丢脸叙事链驱动**
- 禁止第一段就让\"中国主动、中国被拒、中国被定性\"成为主线

- **禁止\"当场被拒\"4字单独成段**——单独成段会把羞辱感放大到全文基调

### 外媒引用规则
- **不得引用\"外媒/外方官员批评中国不够认真/能力不足/别有用心\"等定性表述**，即使有确切信源也删

- 可以保留的外媒引用：技术能力描述、市场数据、政策分歧描述（如白宫内部部门之争）
- 所有对中国主体（政府/企业/人员）的负面外方定性，一律不转述

### 结尾方向规则
- **结尾不得以\"中国被排除/中国没有席位/中国怎么办\"等被动姿态收束**
- 正确方向：以\"国产替代加速/国内行业追赶/市场增长空间\"等积极追赶快节奏收束
- 呼应正文中的正面数据（如 IDC 预测 37 倍增长）做收束锚点
- 可以抽象幽默,但不低俗
- 可以假正经,但不能故作高深

## 实战必杀技：100%人工写作法（2026-05-28 用户手改朱雀100%人工验证）

以下手法来自用户亲手改写段永平文章后朱雀检测**100%人工**的成绩，写style-c时必须优先执行。

### 1. 段落碎到极致
- 一句话一段，用「！」替代「。」
- 不要怕段落碎——碎=活人打字的感觉
- 示例：
  > ❌ 我的版本：重磅消息。段永平买成了泡泡玛特第二大股东
  > ✅ 用户版本：重磅消息！段永平买成了泡泡玛特第二大股东；段永平是谁？步步高、OPPO、vivo的创始人，中国商界公认的「教父」级人物；他很少出手买公开市场的股票

### 2. 加具象挂钩
- 不要让读者猜这个产品/公司是干啥的
- 直接说一个读者100%知道的关联物
- 示例：「女大学生特别喜欢的拉布布就是泡泡玛特的」→ 读者一秒定位，不用解释公司是什么

### 3. 活人称谓语
- 「段总」「大哥」替代「段永平」
- 「我们这些人」拉近距离，不居高临下

### 4. 去术语化判断
| 别说 | 要说 |
|:----|:----|
| 护城河 | 到底牛在哪里 / 不一样的东西 |
| 最值钱的一层 | 最重要的一层 |
| 他看的不可能是短期 | 他看的肯定不是短期 |
| 这件事有意思的地方就在这里 | 大哥肯定是有说法的 |

「大哥肯定是有说法的」——三个字替代十句分析。不是分析判断，是活人直觉。

### 5. 关键人物加一句背景说明
提到乔布斯，加一句「大家都知道是传奇」→ 让读者感觉作者知道我在想什么

### 6. 语气词点缀
结尾「你怎么看呢」替代「你怎么看」。每篇至少出现2次（呢/啊/嘛/吧）

`XXX：YYY` 句式视同冒号引导判断句，正文里尽量改成自然句，不用`：`做硬转折。
- ❌ 一个服务商给的数据很诚实：成功率大概50%
- ✅ 一个服务商给的数据很诚实 / 成功率大概50%
- ❌ 底层报价很透明：每月1200元起
- ✅ 底层报价很透明 / 每月1200元起
- 例外：直接引语（「某人说：XXX」）、列举标题（「XX有三大问题：一、二、三」）可保留冒号，但列标题本身视项目符号规则决定是否允许

### 四、执行补充规则
- 不只禁原句，所有同一路数的 AI 推进句、模板转折句、伪洞察句一并禁用
- 禁止为了制造“分析感”而使用机械转折、前后对照、伪深刻总结
- 若一句话读起来像“模型在制造洞察”，即视为高风险句，优先重写
- 若一句话过于像公众号工业模板、行业分析模板或 AI 自动推进句，优先重写
- 允许大白话、口语化、网感，但禁止模板腔、汇报腔、伪高级感

### 五、交稿前新增自检
除原有检查清单外，交稿前必须额外自检：

1. 是否出现用户新增黑名单中的原句
2. 是否出现与黑名单同一路数的相近结构
3. 是否出现“伪洞察句”“模板推进句”“机械转折句”
4. 是否出现明显公众号工业模板味
5. 任一项命中，直接重写，不得交稿

### 六、用户新增黑名单补丁（2026-04-13）
以下句型及近似路数，全部禁用：
- `已经不是什么……是真的……`
- `第一反应不是什么……是什么……`
- `一旦……后面就……`
- `听着……其实……`

以下写法倾向，优先执行：
- 少总结，少提纲式分点，少空洞分析句
- 多用真实案例信息替代概括句
- 当素材里有人物、业务和案例时，优先写“他是谁、他做了什么、他接过什么单子、这些单子说明了什么”

### 七、用户新增用词与文风偏好（2026-04-15 / 2026-04-24）
以下偏好来自用户亲自改写后的版本，后续写 `ai掘金仔 / style-c` 时优先服从。

#### 1. 句子口感
- 优先用直接、顺嘴、像口播一样的句子
- 允许用这种直白写法：`有人借了10万U，用三个月一路亏到退圈`、`另一个人不懂K线，也不会写代码`、`却用 Claude 写出来的 Agent，在10天里滚到20万美金`
- 新增参考口感：`一个人用 Claude Code 把月收入做到6327美元`、`他用AI直接把项目落地、内容分发、用户转化一起跑通了`
- 多用 `一路亏到退圈`、`滚到20万美金`、`抓住AI`、`赚钱思路`、`把项目落地`、`把用户接进来` 这类更接地气的动词和说法
- 少用抽象词，如：`认知系统化`、`半自动化调用`、`投机场景`、`分发机制`，除非素材本身必须这么写
- 当文章核心是案例拆解时，优先先抛结果，再用一句话点明“他到底把什么跑通了”

#### 2. 段落推进方式
- 用户更偏好用连续提问推进段落，而不是作者先下定义
- 可优先使用这种推进：`究竟人工智能是否可以实现自己给我们赚钱？`、`不过这套赚钱路子能不能走得长远？`、`怎么借鉴其赚钱思路？`
- 小标题或分段引导语可以更直白，如：`先看她是如何操作的`
- 新增结构偏好：先给结论句，再补支撑材料；尤其是每一节开头，优先直接点明这一节的结论，不要先绕一圈
- 当用户已经把案例改成“先结论后展开”时，后续稿件沿用这个顺序，不要改回分析稿式铺垫
- 允许更像“把门道摊开讲”的问答式推进，不要总写成“我来拆底层逻辑”的分析稿

#### 3. 选词偏好
- 用户偏好：借了、一路亏、退圈、滚到、赚钱路子、抄作业、借鉴、赚钱思路、抓住AI、放大收益
- 新增偏好：`把项目落地`、`把赚钱路径跑通`、`把内容分发接上`、`把用户转成持续付费的人`、`代码只是起点`
- 少用：抽象、骚、味道、门道、这东西、这玩意儿、系统化调用、广场流量这类偏模型化/评论化表达
- 除项目名、产品名、必要工具名外，正文尽量用中文，不要堆英文术语；像 `MRR`、`ARR`、`views`、`followers` 这类默认优先改成中文表述
- 以下表达列入禁用或高风险替换：`第一反应是一个写代码工具`、`再往里看`
- 允许保留大白话，但不要为了 style-c 强行塞过多网络腔

#### 4. 结构与信息取舍补充
- 当用户要写“AI 变现案例 / 项目拆解”时，重点优先级固定为：
  1. 这个项目怎么落地
  2. 具体怎么分发和转化
  3. 最后怎么形成持续收入
- 少写行业评论，多写路径
- 少写泛泛判断，多写动作链
- 可优先采用这种顺序：`先抛结果 → 点明跑通了什么 → 介绍产品是什么 → 拆赚钱路径 → 收尾判断`
- 用户当前偏好把“这一节的结论句”放在该节最前面，例如：`BridgeMind卖的是一套有人持续付费的工具订阅`
- 不要过度罗列参数和数字，数字够支撑判断即可；如果同一趋势已有多个数字，优先保留最能说明“持续上涨/持续收钱”的那几个

#### 5. 收尾要求补充
- 用户版本更偏好“给出可借鉴动作”而不是纯评论区提问
- 若用户明确想要方法论收束，可以写“怎么借鉴其赚钱思路”这一类收尾导向
- 对 `ai掘金仔` 账号，允许保留固定群引流口播
- 但仍然禁止在非 `ai掘金仔` 稿件里直接切成群引流、卖课、免费算力、带你变现等导流口播；这类表达命中即重写
