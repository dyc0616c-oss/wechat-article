# Anti-AI Skill（降AI）

> **前置：** 写稿和事实核查走 `wechat-article` skill。本skill仅处理降AI（Phase C-D）。

公众号降AI的实战验证体系。核心：**正常写 → 付费工具处理 → 过检**，不刻意写差，质量第一。

---

## 核心结论（2026-05-30 更新）

**路线选择取决于用户有无付费工具：**

| 路线 | 适用场景 | 说明 |
|:----|:--------|:-----|
| **版本B ✅** | 用户有付费降AI工具 | style正常格式 + 大白话 → 付费工具处理（已实战验证41%人工） |
| **版本C ✅** | 用户无付费工具 / 明确要求手动降 | style正常格式 → 手动轻量降AI（2026-05-30实战验证可行） |

**铁律：不刻意写差、不制造语法瑕疵、不搞啰嗦细节。质量第一，检测第二。**

**⚠️ 关于手动降AI（2026-05-30 更新）**

手动降AI曾经失败的原因是**大改结构+改成了群聊体**，原文章骨架被破坏。如果只做**语言层面的轻量替换**（加口语标记、换高频词、调节奏），不碰格式，效果可行。2026-05-30实战验证：两篇文章（链小智style-thinks-ai + Ai吹哨兵style-c）手动降AI后用户未提出否定。

**手动降AI的正确姿势：**
- ✅ 只在**语言层面**工作：加口语标记、换高频词、拆长句、调语序、改连接词
- ✅ **格式零改动**：胶囊小标题不动、图片顺序不动、HTML骨架不动
- ✅ **保留原文信息密度和逻辑连贯性**，不为了降AI故意写废话或破坏逻辑
- ❌ 不自行切换为群聊体/午夜好友体——那是朱雀0%时用户明确要求的最后手段

**什么时候可以尝试手动调整：**
- 用户明确要求「你试试」「你先自己降」——直接动手，不用再问
- 用户说「降AI」但方向不明确——先问用户有无付费工具，无则做手动轻量替换
- 如果手动降AI被用户否定 → 恢复原始版本，承认手动不如付费工具，让用户决定下一步

### ⛔ 手动降AI禁区（2026-05-28 + 2026-05-29 + 2026-06-02 用户纠正实战教训）

#### 禁区一：不要破坏HTML排版结构（2026-05-29 新教训）

**手动降AI时，语言可以改，格式不能动。** 这是两条独立的线——改语气/词汇/节奏属于内容降AI；删胶囊小标题/改图片顺序/破坏模板结构属于毁格式。

| ❌ 错误做法（被用户纠正） | ✅ 正确做法 |
|:------------------------|:----------|
| 为了降AI把胶囊式小标题（`<div class="titlestyle">`）全部删掉，变成无标题的碎段落 | 保留胶囊式小标题和img-wrap→titlestyle→正文的结构顺序不变 |
| 重新编排段落顺序、打乱每节的内容归属 | 保持原文的节划分不变，只改节内的语句 |
| 改变封面图/配图位置（把封面图下移、删除某节配图） | 保留封面图→首段→配图→标题→正文的完整结构 |

**自检清单（降AI后交付前强制核查）：**
- [ ] 胶囊式小标题（`<div class="titlestyle"><span>...</span></div>`）是否还在？
- [ ] 每节图片（`<div class="img-wrap">`）是否还在对应小标题正上方？
- [ ] 封面图是否还在标题摘要下方、首段正文之前？
- [ ] HTML结构是否仍然是：标题→摘要→封面图→首段→（配图→小标题→正文）×N→结尾？

如果以上任何一项不通过，不要交付——先把格式恢复正确再降AI。

#### 禁区二：不要尝试重写为群聊体/极碎段落格式来降AI

**不要尝试重写为群聊体/极碎段落格式来降AI。** 用户已明确表示手动大改后的版本不如原版。

| ❌ 错误做法（被用户否决） | ✅ 正确做法 |
|:------------------------|:----------|
| 把正经文章手动重写为「群聊体」——碎成单句段落、加"笑死""给小编看傻了"等语气词 | 保持原文章结构和风格不变，仅做轻量微调 |
| 大幅改变段落节奏、删除过渡句、人为制造"不完整感" | 保持原文信息密度和逻辑连贯性 |
| 强行注入情感标签和感叹号 | 保持原有情绪浓度，不过度修饰 |

**手动降AI的正确范围：**
- **语言可以大改**：加口语标记、改句子节奏、拆长句、换动词、插反问/感叹——这些只管内容，不碰结构，放手去做
- **格式不能碰**：胶囊小标题不动、图片顺序不动、每节职责不动。降AI在语句层面工作，不在结构层面工作
- 大幅改结构/风格的版本 → 必须先问用户要不要，不能自作主张
- 如果初次手动降AI后朱雀仍然100%，**不要删格式再试**——应该做更狠的语言改造（加更多口语标记、用更碎的句子节奏、插更多反问），而不是取消格式

**如果用户说"去AI"但你没有付费工具可用 → 先问用户有无所付费工具。若用户说没有或让你直接动手，执行手动降AI流程（见下方「手动降AI实操清单」）。直接动手，不要再问。**

**⚠️ Ai掘金仔（style-money）手动降AI的历史教训（2026-06-02）：**
用户曾对Ai掘金仔版本A的手动降AI版本明确表示「还不如原来的」，要求恢复原版。如果你的手动降AI版本被用户否定，立即恢复原始版本，承认手动不如付费工具，不再二次尝试。**不要在用户否定后继续改第三版。**

## 完整工作流

### Phase A：写稿（正常写，不管AI检测）
按目标账号风格正常写稿，专注内容质量。

### Phase B：事实核查 ⛔ 硬停
写完后，执行 `wechat-article` skill 的 Step 6 事实核查：
- 逐句提取可验证声称（数字/产品名/事件/因果/对比）
- 逐个搜索核实
- ❌ 标记 = 修正后重新核查，不得跳过
- 全部 ✅ 后才进入下一步

**事实核查通过后，必须停下来问用户：「要开始降AI吗？」**

### Phase C：降AI处理（用户确认后才执行）

**先确认用户有无付费降AI工具：**
- 有 → 付费工具处理（最优，可达到41%人工）
- 无 / 用户说「你先自己处理」→ 执行手动降AI，详见 `references/manual-deai-checklist.md`

手动降AI时按以下流程（流程编号从后面的Step 3继续）：

1. **格式保护** — 降AI改写后，必须与原HTML对比，确认以下格式结构未被改动：
   - 胶囊式小标题（`<div class="titlestyle">`）未删除
   - 每节图片在小标题正上方（img-wrap → titlestyle 顺序）
   - 封面图位置未变
   - 内容/节划分未重新编排
   - **如果格式被破坏了，先恢复格式再交付**

2. **图片检查** — HTML里的所有 `<img src="图片/xxx">` 对应的文件必须实际存在于同级 `图片/` 目录

3. **输出纯文本** + 朱雀检测地址，让用户自行检测

### Phase D：记入降AI日志

降AI完成后（无论手动还是付费工具），写入 `references/deai_log.db`（SQLite，仅 `changes` 表）：
- date / account / article_title
- replaced_words：改了哪些高频词（「赋能→帮助」「综上所述→说到底」）
- sentence_changes：调整了哪些句式（拆长句×3、合并短句×1）
- markers_added：加了哪些口语标记（说白了×1、你发现没有×1）

查询命令（下次会话可直接用）：
```bash
# 查最近5条记录
sqlite3 ~/.hermes/skills/content-creation/anti-ai/references/deai_log.db "SELECT date, account, article_title FROM changes ORDER BY id DESC LIMIT 5;"
# 查某账号的所有记录
sqlite3 ~/.hermes/skills/content-creation/anti-ai/references/deai_log.db "SELECT date, replaced_words, sentence_changes FROM changes WHERE account='Ai吹哨兵' ORDER BY id DESC;"
```

正常风格+大白话+付费工具处理1-2轮 = 40%+人工率。

## Step 4：8步降AI改写流程（备用方案）

朱雀人工<30%时启用。按顺序执行，通过就停。

### 第1步：基础降AI痕迹
保留核心信息，减少完美句式，加入不规则表达；穿插口语化；打破机械化段落。

**检查：** 连续排比？打断。每句太完整？留话只说一半。

### 第2步：句子润色
替换平淡词汇；调整句式；修语法。

**检查：** 能用更具体词替换？节奏单调？

### 第3步：简化结构
拆长句（超30字拆开）；短聚焦段落；删模糊表达。

**检查：** 每段只讲一件事？长句拆了？

### 第4步：语气适配
按账号调语气（犀利/接地气/专业客观）；控术语密度。

### 第5步：丰富细节
加案例、数字、背景；替换抽象表述。

### 第6步：精简冗余
删重复、多余修饰；减程度词。

### 第7步：优化节奏
长短句交替；调段长；插问句/感叹句。

### 第8步：主题扩写
补关联信息与多元观点；加真实案例和数据。

**注意：** 先加细节（Step 5）再删废话（Step 6）——顺序关键。

## Step 5：口语化改造标记库（Paper-Master 吸收）

在文章合适位置注入以下标记，每200-300字至少1处：

| 语境 | 标记 | 示例 |
|:----|:-----|:-----|
| 引出新观点 | 说到这儿 / 那么问题来了 / 你发现没有 | 「说到这儿，一个更深的问题浮现出来了」 |
| 递进深入 | 进一步说 / 更关键的是 / 退一步讲 | 「进一步说，这不仅仅是一个...」 |
| 补充说明 | 说白了 / 实际上是这样 / 仔细想想 | 「说白了，这就是在...」 |
| 反向思考 | 反过来看 / 换一个角度 / 与之相对 | 「反过来看，恰恰是...」 |
| 情感强化 | 说真的 / 不是我说 / 真的很... | 「说真的，这种感觉我太懂了」 |
| 追问引导 | 明白不？/ 你猜怎么着？/ 为什么呢？ | 「明白不？因为...」 |
| 口语连接 | 这就让 / 于是 / 接下来 / 然后呢 | 「这让对方一下子就...」 |
| 语气词点缀 | 呢 / 了 / 的 / 吧 / 嘛 | 「说到底呢，其实就是...」 |

**使用频率：** 每200-300字至少1处。同一标记全文不超过3次。自然分布，不刻意每段都塞。

## Step 6：段落节奏黄金法则（Paper-Master 吸收）

### 法则一：三句一组黄金频率
核心信息以「观点 → 解释 → 情感重击」三拍子节奏出现：
```
不是你"太粘人"
"没安全感"
是你的情感需求，一直在挨饿
```

### 法则二：长短句交替
- 不允许连续3个以上等长句子
- 长句（40字+）后跟短句（10-15字），制造呼吸感
- 短句可独立成段

### 法则三：段落长度差异化
- 关键论点独立成短段（2-3行）
- 故事段落适度拉长（4-6行）
- 相邻段落长度差至少30%

### 法则四：空行即是标点
- 段落之间频繁空行
- 情绪转换处必须空行
- 每200-300字至少一次空行分隔

## Step 7：故事案例法则（Paper-Master 吸收）

### 法则一：案例必须是真实的第三方故事
- ❌ 禁用：「我有一个朋友」「我认识一个人」这类虚构第一人称
- ✅ 正确：引用真实新闻事件、名人真实经历、历史典故——有出处、可查证
- 用第三人称讲述：「有个叫阿欢的姑娘」「认识个做运营的，叫老王」
- 即使是用化名，故事骨架必须是真实事件

### 法则二：案例要有完整结构
引入（谁，什么情况）→ 冲突（发生了什么）→ 结果（变成什么样了）→ 教训（我从中悟到了什么）

### 法则三：正反案例成对出现
讲坏结果案例，必须跟一个好结果案例形成对比。

### 法则四：案例与金句交替
案例（150-400字）→ 归纳金句（1-2句）→ 案例（150-400字）→ 归纳金句（1-2句）

**故事来源优先级：**
1. 真实新闻事件（搜索确认）⭐ 首选
2. 真实历史典故/名人事迹
3. ❗ 以上都找不到 → 可编造第一人称故事兜底（「我有个朋友叫阿欢……」，底线：不虚构事实性数据/金额/机构名）

## Step 8：情绪调动五步法（Paper-Master 吸收）

| 步骤 | 操作 | 读者心理 |
|:----|:-----|:---------|
| 1. 建立共鸣 | 开头用具体场景让读者觉得「这就是我」 | 「你怎么知道我的事？」 |
| 2. 揭示真相 | 给出反常识或意外的解释 | 「原来是这样？」 |
| 3. 制造焦虑 | 用极端案例或数据说明严重性 | 「不改变会很糟」 |
| 4. 给出方法 | 具体的行动建议或认知工具 | 「我有办法了」 |
| 5. 赋能收束 | 以强烈信念注入收尾 | 「我可以做到」 |

**应用规则：** 前两步在文章前30%完成。第四步必须够具体。

## 核方案A：午夜好友人格（Midnight-Friend）

当标准路线+8步流程后人工仍<30%，切换此人格。实测朱雀39%人工。

**核心参数：**
- 用真实人物故事替代虚构第一人称
- 文章有自我质疑、不确定感
- 大部分段落3句以内，25%段落只有1句话
- 克制开头→中间爆发→结尾不收束
- 结尾自然变淡，不总结不升华

| 你的写法 | midnight-friend写法 |
|:---------|:-------------------|
| 开头用新闻事件 | 开头用一个具体的第三方人物时刻 |
| 数据→解读→意义三段完整 | 数据→真实反应→再看一遍→觉得不对劲 |
| 段落均匀3-5句 | 25%段落只有1句话 |
| 结尾问读者「你怎么看」 | 结尾自然变淡 |

## 核方案B：群聊体格式（最后手段）

当标准文章格式持续返回**0%人工**时使用。从体裁上完全放弃文章结构。

### 规则
1. 无标题、无摘要、无小节、无金句
2. 空格替代部分标点（像手机打字）
3. 「刚刷到一条视频」「刚在tg群里看到」开头
4. 不用「我有一个朋友」框架，直接讲故事
5. 话题硬切不过渡
6. 不总结不升华，自然变淡结束
7. 段落 = 1-2个想法，不是句子

## 完稿自检清单（Paper-Master 吸收细化）

### 标题层
- [ ] 标题有明确阅读承诺
- [ ] 用了至少一种爆款策略（悬念/反常识/对号入座/数字/提问）
- [ ] 不是AI万能模板

### 开头层
- [ ] 前50字内出现具体的人、动作或场景
- [ ] 没有「在这个快节奏的时代」「有人说」「你是否曾经」

### 内容层
- [ ] 至少1个完整的具体故事（有人物、有经过、有结果）
- [ ] 所有案例有真实来源
- [ ] 金句密度适中（每150-300字1个）
- [ ] 没有连续3句以上无具体内容的空洞段

### 节奏层
- [ ] 没有连续3个以上等长句子
- [ ] 相邻段落长度有明显差异
- [ ] 每200-300字至少一次空行
- [ ] 至少1个单句独立成段的强调段

### 语气层
- [ ] 全文至少5处口语化标记
- [ ] 没有「首先其次再次最后」和「综上所述」
- [ ] 「你」每200字至少出现1次

### 结尾层
- [ ] 有明确收束动作（金句/行动号召/互动引导）
- [ ] 不是空洞口号

### 真实性层
- [ ] 所有引用的新闻/名言/数据均可查证
- [ ] 没有虚构案例

## Step 9：高频AI词替换速查表（humanize-chinese 吸收）

以下是从 humanize-chinese 的 221 个替换模式中，摘选最适合公众号文章的。写完稿子后，全文搜索左边的高频AI词，随机替换为右边的自然说法。

### 逻辑连接词（最容易暴露AI）
| 高频AI词 | 替换为 |
|:--------|:-----|
| 值得注意的是 | 注意 / 要提醒的是 / 特别说一下 |
| 综上所述 | 说到底 / 简单讲 / 总之 |
| 不难发现 | 可以看到 / 很明显 |
| 与此同时 | 同时 / 这时候 |
| 因此 | 因而 / 为此 / 故而 |

## Step 10：AI特征信号检查表（humanize-chinese 吸收）

写完稿后扫一遍这些信号，但凡命中两项就必须改：

### 🔴 致命信号（一项都不能有）
- [ ] **三段式结构**：开头铺背景 + 中间论证 + 结尾总结升华
- [ ] **机械连接词链**：「首先...其次...再次...最后」完整序列
- [ ] **空洞大词**：「推动作用」「重要意义」「显著进展」「全方位提升」

### 🟠 高危信号（超过1项就危险）
- [ ] **AI高频词密度高**：上面 Step 9 的词每千字超5个
- [ ] **对称排比**：「不仅...而且...」「一方面...另一方面...」
- [ ] **模板句式**：「在当今...时代」「随着...的发展」「不仅...更...」
- [ ] **填充短语**：「值得注意的是」「总而言之」「众所周知」

### 🟡 中危信号（超过2项需关注）
- [ ] **虚化表达**：「可以说」「在一定程度上」「基本上」「某种程度上」
- [ ] **列表成瘾**：连续出现编号列表（1/2/3或第一/第二/第三）
- [ ] **标点密度异常**：每千字破折号>5个 / 分号>3个
